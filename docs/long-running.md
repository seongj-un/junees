# 장기 실행 하네스 계획

Junees가 컨텍스트 창 하나에 담기지 않는 큰 작업을, 여러 세션에 걸쳐 끊기지 않고 이어 가게 만드는 단계들이다.
설계는 Anthropic의 "Effective harnesses for long-running agents"(초기화 에이전트 + 작업 에이전트, 기능 목록, 진행 기록, git 체크포인트)를 따른다.

각 단계는 PR 하나이고, PR마다 Momus 리뷰를 받고 반영한 뒤 CI가 통과하면 main에 merge한다.
이 문서는 진행 상황을 기록하는 장부이기도 하다. 단계가 끝나면 아래 상태를 갱신한다.

## 핵심 원칙

- 기록은 디스크가 진실이다. 프로세스가 언제 죽어도 마지막으로 기록된 지점에서 다시 시작할 수 있어야 한다.
- 모델의 "다 했다"는 말을 믿지 않는다. 완료는 하네스가 확인한 검증(테스트, 명령 종료 코드)으로만 인정한다.
- 한 세션은 기능 하나만 끝낸다. 세션이 끝날 때 작업 트리는 커밋된 깨끗한 상태여야 한다.
- 무인 실행은 예산(토큰, 시간, 세션 수)과 정지 조건 안에서만 돈다.

## 단계

### L1. 세션 기록과 재개
- 대화의 모든 변경을 `$JUNEES_HOME/sessions/<id>.jsonl`에 바로 추가 기록(append-only, 기본 `~/.junees`)
- `--continue`(현재 폴더의 마지막 세션), `--resume <id>`, `--no-session`, 대화 중 `/sessions`
- 재개할 때 기록 검증: 마지막 줄이 잘렸으면 무시, 결과 없는 tool_use는 "중단됨" 오류 결과로 채움
- 토큰 사용량도 기록하고 복원

### L2. 컨텍스트 관리
- 프롬프트 캐싱(system, tools, 최근 메시지에 `cache_control`)
- 응답의 usage로 현재 컨텍스트 크기 추적
- 한도에 가까워지면 오래된 도구 결과 내용을 비우고(context editing), 그래도 넘치면 앞부분을 모델 요약 한 메시지로 압축(compaction)
- 컨텍스트 초과 400을 받으면 압축 후 한 번 재시도

### L3. 장기 작업 모드
- `junees task init "<목표>"`: 초기화 세션이 `.junees/features.json`(기능 목록, 각 항목의 검증 방법, `passes: false`), `.junees/progress.md`, `.junees/init.sh`를 만들고 첫 커밋
- `junees task run`: 새 컨텍스트의 작업 세션을 반복. 각 세션은 진행 기록과 `git log`를 읽고, 안 끝난 기능 하나를 골라 구현하고, 검증하고, 커밋하고, 진행 기록을 남긴다
- 하네스가 강제하는 규칙: 작업 세션은 기능 목록의 `passes`만 바꿀 수 있다(설명 수정이나 항목 삭제 거부). `passes: true`는 그 기능의 검증 명령이 하네스 쪽에서 성공해야 인정. 세션이 끝났는데 작업 트리가 더러우면 하네스가 체크포인트 커밋
- 정지 조건: 모든 기능 통과, 예산 소진, 연속 N세션 진전 없음

### L4. 무인 실행 안정성
- 예산: 작업 전체 토큰 상한, 시간 상한, 세션 수 상한
- Ctrl-C/SIGTERM: 현재 도구가 끝나면 멈추고 짝 없는 tool_use를 채움(#2)
- 무인 모드 명령 정책: 위험 명령 차단 목록, 작업 폴더 밖 쓰기 경고
- 실행 로그 파일, 크래시 후 `task run`이 기록에서 이어서 시작

### L5. 상태 보기와 알림
- `junees task status`: 기능별 통과 여부, 세션 수, 토큰 사용량, 최근 진행 기록
- 작업 완료나 정지 시 알림(디스코드 웹훅)
