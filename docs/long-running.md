# 장기 실행 하네스 계획

Junees가 컨텍스트 창 하나에 담기지 않는 큰 작업을, 여러 세션에 걸쳐 끊기지 않고 이어 가게 만드는 단계들이다.
설계는 Anthropic의 "Effective harnesses for long-running agents"(초기화 에이전트 + 작업 에이전트, 기능 목록, 진행 기록, git 체크포인트)를 따른다.

각 단계는 PR 하나이고, PR마다 Momus 리뷰를 받고 반영한 뒤 CI가 통과하면 main에 merge한다.
이 문서는 진행 상황을 기록하는 장부이기도 하다. 단계가 끝나면 아래 상태를 갱신한다.

## 핵심 원칙

- 기록은 디스크가 진실이다. 프로세스가 언제 죽어도 마지막으로 기록된 지점에서 다시 시작할 수 있어야 한다.
- 모델의 "다 했다"는 말을 믿지 않는다. 완료는 하네스가 확인한 검증(테스트, 명령 종료 코드)으로만 인정한다.
- 한 세션은 기능 하나만 끝낸다. 세션이 끝날 때 작업 트리는 커밋된 깨끗한 상태여야 한다.
- 무인 실행은 예산(토큰, 시간, 세션 수)과 정지 조건 안에서만 돈다.

## 단계

### L1. 세션 기록과 재개
- 대화의 모든 변경을 `$JUNEES_HOME/sessions/<id>.jsonl`에 바로 추가 기록(append-only, 기본 `~/.junees`). 항목은 `meta`(첫 줄, 형식 버전 `format: 1` 포함), `message`, `append_text`(실패한 턴 뒤 입력이 마지막 user 메시지에 합쳐짐), `usage`. 모든 줄에 기록 시각 `ts`(unix 초)
- 쓰는 동안 세션 파일을 `flock`으로 잠가서, 실행 중인 세션은 다른 Junees가 이어 가거나 고칠 수 없다. 파일 `0600`, 폴더 `0700`
- 지원하는 것보다 새 `format`의 세션은 오류로 거절(L2에서 새 항목 종류를 넣을 때 `FORMAT`을 올린다)
- 에이전트와 복원이 같은 `Transcript::apply`로 기록을 재생하므로 복원 결과가 실행 중 기록과 같다
- `--continue`/`-c`(현재 폴더에서 마지막으로 기록된 세션), `--resume <id>`(유일한 앞부분 허용), `--no-session`, 모두 `-p`와 함께 사용 가능. 대화 중 `/sessions`, `/reset`은 새 세션
- 재개할 때 기록 검증: 줄바꿈 없이 끝난 마지막 줄이 읽히지 않으면 잘린 쓰기로 보고 버리고 파일에서도 잘라 냄(줄바꿈까지 있는 줄이 읽히지 않으면 위치와 상관없이 오류), 결과 없는 tool_use는 "interrupted" 오류 결과로 채우고 그것도 기록
- 다른 폴더에서 시작한 세션을 이어 가면 시작 폴더를 한 줄로 알림. `JUNEES_HOME`과 `HOME`이 없으면 기록 없이 실행(`-c`/`--resume`만 오류)
- `/sessions`는 각 파일의 meta 줄과 첫 항목만 읽는다
- 토큰 사용량도 기록하고 복원(`/usage`는 현재 세션 기준)
- 기록 쓰기가 실패하면 경고 한 번, 그 세션의 나머지는 기록하지 않음
- 새 세션 파일은 첫 항목을 쓸 때 만든다(빈 세션이 `-c` 후보가 되지 않도록)

### L2. 컨텍스트 관리
- 프롬프트 캐싱: 직렬화 단계에서 마지막 도구, system(텍스트 블록 배열), 마지막 메시지의 마지막 블록에 `cache_control: ephemeral`(한 번만 보내는 요약 호출은 제외). `Usage`에 캐시 쓰기/읽기 토큰을 더하고 `/usage`에 표시
- 컨텍스트 크기 = 마지막으로 잰 응답의 입력(캐시 포함) + 출력 + 그 뒤 더해진 블록의 추정치(JSON을 글자 단위로: ASCII 4글자당 1토큰, 한글/한자/가나 1글자당 1토큰, 그 밖의 비ASCII는 4바이트당 1토큰. #28). `JUNEES_CONTEXT_WINDOW`(기본 200000), `JUNEES_COMPACT_THRESHOLD`(기본 0.8). `/context`로 확인
- 모델 호출 직전에 크기가 한도 이상이면 최근 3개를 뺀 도구 결과 메시지의 출력을 비운다(context editing, 짝과 `is_error` 유지). 항목 `clear_tool_results { upto }`
- 비울 것이 없거나 비운 뒤 다음 응답도 한도 이상이면 압축(compaction): 최근 두 사용자 입력(안 되면 하나) 앞에서 자르고(도구 결과로 시작하거나 짝을 쪼개는 지점 금지), 앞부분을 도구 없는 요약 호출로 요약해 꼬리 첫 user 메시지 앞에 붙인다. 입력이 하나뿐인 긴 턴(L3 작업 세션 형태)은 도구 결과만 든 메시지 다음 assistant 메시지에서 자르고(최근 도구 왕복 두 번 유지), 요약과 원래 입력 원문을 담은 user 메시지를 앞에 넣는다. 요약 실패, 빈 요약, `max_tokens`로 잘린 요약이면 경고만
- 압축은 세션 파일을 새로 쓰지 않고 `compact { summary, keep_from }` 항목을 추가하는 방식으로 남긴다(`Transcript::apply`가 처리하므로 "재생 결과 = 실행 중 기록"이 유지됨). 요약 호출 사용량은 `summary_usage`(사용량에는 더하고 컨텍스트 크기에는 안 씀). 새 항목 때문에 `FORMAT`을 2로 올렸고 형식 1 세션도 읽는다
- `/compact`로 수동 압축, 압축하면 CLI에 한 줄 표시
- 컨텍스트 초과 400을 받으면 강제로 비우기+압축, 이어서 최근 것까지 모든 도구 결과를 비운 뒤 한 번만 재시도(줄어든 게 없으면 재시도 없이 오류)
- 형식 1 세션을 L2로 이어 쓰면 meta는 형식 1 그대로라 L1 바이너리는 `line N is corrupt`로 거절한다(파일은 안전). L2부터는 모르는 항목 종류를 "continued by a newer Junees"로 알린다
- 웹 검색(서버 도구, `JUNEES_WEB_SEARCH`): 검색 블록(`server_tool_use`, `web_search_tool_result`)은 원본 그대로 두고 다시 보낸다. 도구 결과 비우기는 이 블록을 건드리지 않는다(`encrypted_content`를 바꾸거나 빼면 400이고, 짝을 지우면 뒤 텍스트의 인용이 가리킬 곳이 없다). 압축 요약 텍스트에는 검색어와 앞 5개 결과의 제목/URL만 넣는다. 검색한 호출의 사용량은 API의 검색 반복마다 읽은 캐시가 모두 더해져 실제 크기보다 커서 컨텍스트 크기로 쓰지 않는다(검색 없는 다음 호출이 다시 잼). 그 사이 크기는 마지막 측정 + 이후 블록 추정치로 잡아 매 호출이 검색하는 세션도 제때 압축한다(#23, 재생으로 계산하므로 새 항목 없음). 턴이 결과 없는 `server_tool_use`를 남기고 끝나면(pause 상한, 취소, 오류) 새 입력 전에 그 호출을 `drop_server_calls` 항목으로 지우고 경고한다(#23, 새 항목이라 `FORMAT` 4). 그런 호출이 마지막 응답이 아닌 곳에 있으면 뒤 thinking 블록의 앞부분이 바뀌므로 `clear_tool_results { upto: 0 }`로 thinking 블록을 모두 지운다(#28, 수동 thinking 예산 모드 제외. 기존 항목이라 형식 그대로). 텍스트의 `citations`는 기록에 남는 필드라 이전 바이너리는 읽을 때 버리지만(인용 없는 텍스트로 보냄) 거절하지는 않으므로 `FORMAT`은 올리지 않았다
- 확장 사고 블록 보존(#3): 응답의 thinking, redacted_thinking, 서버 도구 블록을 `ContentBlock::Other`(원본 JSON)로 기록과 세션 파일에 그대로 남기고 다음 요청에 그대로 보낸다. 캐시 표시는 마지막 메시지의 마지막 일반 블록에, 요약 요청의 텍스트에서는 thinking을 빼고 다른 원본 블록은 종류만 적는다. 이런 블록을 이전 바이너리가 자리표시로 잘못 읽지 않도록 `FORMAT`을 3으로 올렸다. `JUNEES_THINKING_BUDGET`(기본 0, 켜면 1024 이상이고 `JUNEES_MAX_TOKENS` 미만)으로 확장 사고를 켜며, 요약 호출에는 쓰지 않는다. Claude 5.1 이후 모델의 thinking 앞부분 검사 때문에 비우기와 압축은 기록의 thinking 블록을 모두 지우고, 예산을 켠 수동 모드(검사 없는 4.6 이하 모델)에서는 지우지 않는 대신 한 턴 안의 압축을 턴 전체 요약으로 바꿔 턴이 thinking으로 시작하게 한다(`keep_thinking`). 형식 2 이하 세션을 이어 쓰면 `format` 항목을 덧붙여 이전 바이너리가 열지 않게 한다

### L3. 장기 작업 모드
- 작업 파일은 대상 저장소의 `.junees/`에 둔다. `features.json`(기능 목록: `id`, `description`, `verify` 셸 명령, `passes`), `progress.md`(사람이 읽는 진행 기록, 세션과 하네스가 함께 덧붙임), `state.json`(하네스 상태, `.junees/.gitignore`로 git에서 제외)
- `junees task init "<목표>"`: git 저장소가 아니면 오류(자동 `git init` 없음), 이미 `features.json`이 있거나 작업 트리가 더러우면(`.junees/` 제외) 오류. 초기화 세션(목표를 검증 가능한 기능 5~50개로 쪼개고 verify 명령을 정하고 `progress.md`를 쓰라, 필요하면 `init.sh`, 아직 구현하지 말라)이 끝나면 하네스가 목록을 검증(JSON 배열, 비어 있지 않음, id 유일, verify 존재, 전부 `passes: false`, verify를 한 번씩 실행해 이미 통과하는 것 거절, 문제를 모두 나열)하고, 틀리면 오류 내용을 같은 세션에 보내 한 번 더 고치게 한다. 그래도 틀리거나 세션이 실패하면 목록을 `features.rejected.json`으로 옮겨 init을 다시 할 수 있게 한다. 통과하면 하네스 서식으로 다시 쓰고 `junees: initialize task`로 커밋
- `junees task run [--max-sessions N]`(기본 20): 작업 트리가 더러우면 거절. 시작할 때 파일에서 `passes: true`인 기능의 verify를 다시 실행해 실패하는 것은 통과에서 뺀다(경고와 progress 한 줄). 재검증이 작업 트리를 바꿨으면 세션 전에 `junees: recheck passing features at run start`로 커밋해서, 세션 없이 정지해도 트리가 깨끗하다(이슈 #11). 세션마다 새 `Agent`(새 컨텍스트, L1 세션 기록). system 프롬프트에 규칙, 기능 목록과 통과 여부, `progress.md` 마지막 4000자, `git log --oneline -20`. 첫 입력은 "안 끝난 기능 하나를 골라 구현, 검증, 커밋하고 progress.md를 갱신하라"
- 하네스가 강제하는 규칙: `passes`는 전용 도구 `mark_feature_passing {id}`로만 바뀐다. 하네스가 verify 명령을 저장소 루트에서 bash 도구와 같은 방식(출력 제한, API 키 변수 제거, 타임아웃 600초)으로 `set -o pipefail`을 붙여 실행하고 exit 0일 때만 저장, 실패하면 출력과 함께 오류 결과. 하네스는 기능 목록의 권위 있는 사본을 들고 있다가 세션이 끝나면 파일을 그 사본으로 되돌려 쓴다(내용이 바뀌었으면 경고와 progress 한 줄, 서식만 다르면 조용히)
- 세션이 끝나면 progress에 하네스 한 줄(세션 번호, 통과 수/전체, 새로 통과한 기능, 토큰)을 붙이고, 작업 트리가 더러우면 `junees: checkpoint after session N`으로 커밋. 하네스의 커밋은 훅과 fsmonitor 없이(`core.hooksPath=/dev/null`, `--no-verify`), API 키 변수 없이 실행하고, 비밀 파일처럼 보이는 새 파일(`.env*`, `*.pem`, `*.key`, ssh 키 등. 비밀 판정은 rename 감지 없이 해서 `.env.example`을 옮겨 채운 `.env`도 잡는다)과 1 MiB가 넘는 새 파일(옮기기만 한 큰 파일은 제외)은 빼고 이유와 함께 경고. 그런 파일만 남아 있으면 다음 실행은 경고하고 시작하고(그 파일들은 이후 커밋에서도 빠지므로), 다른 변경 때문에 더러운 트리를 거절할 때는 파일 이름(세 개까지, 나머지는 개수)과 이유를 보여 준다. `task init`은 git이 아직 무시하지 않는 흔한 빌드 산출물 폴더(`/target/`, `node_modules/`, `/dist/`, `/build/`, `.venv/`, `__pycache__/`, 루트 산출물은 루트에만 걸리게 고정)를 루트 `.gitignore`에 더해 init 커밋에 넣는다. 커밋 전에 `.junees/`와 `.gitignore`를 다시 만든다
- 정지 조건: 모든 기능 통과, 세션 수 상한, 연속 3세션 새 통과 없음(stalled), 세션 오류(오류를 progress에 남기고 체크포인트 후 정지), 세션 뒤 하네스 작업 실패. 턴 한도(`JUNEES_MAX_TURNS`)를 넘긴 세션은 오류가 아니라 세션 종료로 보고 다음 세션으로 넘어간다(stalled 규칙이 처리). 이유를 출력하고 `state.json`에 기록, stalled와 오류는 종료 코드 1
- `state.json`: 실행한 세션 수, 연속 무진전 세션 수, 누적 usage, 마지막 정지 이유. 다음 `task run`은 세션 번호를 이어 간다. 이전 실행이 스스로 멈췄으면(`--max-sessions` 포함) 무진전 횟수를 초기화, 정지 기록 없이 끝났으면(크래시) 이어서 센다. 그래서 `--max-sessions 1`을 반복하면 stalled로는 멈추지 않는다(의도한 동작)
- 예산(토큰/시간), 시그널 처리, 무인 명령 정책은 L4, `task status`와 알림은 L5

### L4. 무인 실행 안정성
- 예산: 작업 전체 토큰 상한, 시간 상한, 세션 수 상한
  - L4b: `task run --max-tokens N`/`JUNEES_TASK_MAX_TOKENS`(작업 전체 누적: init 세션, 요약 호출, 캐시 읽기/쓰기 포함, `state.json`에서 이어 셈), `--max-time`/`JUNEES_TASK_MAX_TIME`(이번 실행의 실제 경과 시간, `90s`/`30m`/`2h`/`1h30m`). 세션 사이와, 세션 안에서는 모델 호출 직전마다(`Agent::with_limit`, 압축 요약 호출 포함), 시작 시 재검증에서는 verify 명령마다 확인하고, 넘으면 그 세션을 마무리(체크포인트 커밋)한 뒤 `budget`으로 정지(종료 코드 0). 시계는 테스트에서 주입
- Ctrl-C/SIGTERM: 현재 도구를 끝내고 짝 없는 tool_use를 채움(#2)
  - L4b: 공유 취소 플래그(`Cancel`, tokio `watch`)를 `Agent::with_cancel`로 넘긴다. 설정되면 모델 호출은 버리고, 실행 중인 도구 호출은 drop되어 bash가 프로세스 그룹 전체를 SIGKILL로 끝내며(정상 종료한 명령의 백그라운드 프로세스는 그대로), 결과 없는 tool_use는 `cancelled by the user` 오류 결과로 채운 뒤 `Cancelled` 오류로 끝난다. 기록은 user 메시지로 끝나서 다음 입력이 붙는다
  - 대화 모드: Ctrl-C는 턴만 취소, 프롬프트에서 두 번(또는 Ctrl-D)이면 종료, SIGTERM은 취소 후 143. `-p`: 취소 후 130/143. `task run`: 세션을 마무리하고 체크포인트 커밋, `interrupted` 정지 이유, 130/143. 두 번째 시그널은 즉시 종료
- 크래시 복구와 실행 로그
  - L4b: `task run`이 저장소 루트 폴더에 `flock`을 잡고(`.junees/`는 세션이 지웠다 다시 만들어지면 잠금이 풀리므로) `state.json`에 `running {pid, started}`와 기능 목록의 하네스 사본을 남긴다. 잠금이 잡혀 있으면 거절, 표시만 남아 있으면 크래시로 보고 `features.json`의 기능 정의를 init 커밋에서 되돌림(사본과 파일에서는 `passes: true`만 가져와 init 커밋의 verify로 시작 시 재검증. 세션이 고칠 수 있는 `state.json` 사본의 정의는 믿지 않음), `progress.md` 한 줄, `junees: recover after crash` 커밋 후 이어 간다
  - `.junees/run.log`: 실행 시작/정지(이유, 토큰, 경과 시간), 세션 시작/끝, 크래시 복구를 UTC 시각과 함께 한 줄씩. git 제외(예전 작업은 첫 실행에서 `.gitignore`를 고쳐 따로 커밋)
  - 남은 것: 크래시 난 세션의 토큰은 누적에 들어가지 않음, 세션이 `.junees/`를 통째로 지우면 잠금과 실행 중 표시도 사라짐
- 무인 모드 명령 정책: 위험 명령 차단 목록, 작업 폴더 밖 쓰기 경고
  - L4a: `bash` 명령 정책(`src/tools/policy.rs`). 실행 전에 루트/홈/상위 폴더 재귀 삭제(그 폴더로 `cd` 한 뒤 `rm -rf *` 포함), 디스크 파괴, 시스템 종료, fork bomb, `curl | sh`, 강제 push, `sudo` 같은 권한 상승을 막고(셸의 표준 입력으로 넘긴 스크립트도 검사) `blocked by policy: <이유>` 오류 결과를 돌려준다. `JUNEES_DENY_COMMANDS`로 접두사 추가, `JUNEES_ALLOW_DANGEROUS=1`로 기본 규칙 끔. 숨길 환경 변수 `JUNEES_HIDDEN_ENV`(#4). 작업 폴더 밖 쓰기와 그 밖의 주의 신호(삭제, `git push`, 패키지 설치 등)는 정책 모듈의 주의 등급(`CommandPolicy::cautions`)으로 찾아 대화 모드에서만 실행 전에 묻는다(`JUNEES_APPROVAL`, `src/approval.rs`). 무인 모드(`-p`, `task`)는 묻지도 경고하지도 않는다

### L5. 상태 보기와 알림
- `junees task status [--json]`: `.junees/`를 읽기만 한다(실행 중인 run 옆에서도 안전, API 키 불필요). 목표, 통과 수/전체와 진행 막대, 기능별 id/통과 여부/설명 첫 줄, 세션 수, 연속 무진전 수, 누적 토큰(입력/출력/캐시), 마지막 정지 이유와 시각, `progress.md` 마지막 5줄. `--json` 필드는 [usage.md](usage.md#장기-작업-모드)에 정리. `.junees/`가 없으면 `task init`을 먼저 하라는 오류
- 이를 위해 `state.json`에 `goal`(init 때 기록)과 `stopped_at`(정지 기록 시각, unix 초)을 추가했다. 둘 다 선택 필드라 예전 파일도 읽힌다. status는 L4b의 실행 중 표시(`running {pid, started}`)와 그 프로세스가 살아 있는지(`kill(pid, 0)`, 잠금은 잡지 않음)로 실행 중/크래시를 구분하고, 표시가 있는 동안에는 기능 목록을 `state.json`의 하네스 사본에서 읽는다(세션이 `features.json`을 직접 고친 통과가 verify 없이 보이지 않도록). `budget`/`interrupted` 정지도 텍스트, JSON, 알림에 그대로 나온다
- 알림: `JUNEES_NOTIFY_WEBHOOK`(디스코드 웹훅 URL)이 있으면 `task run`이 정지를 기록한 뒤 한 번 POST(저장소 이름, 정지 이유 키와 문장, 통과 수/전체, 세션 수, 토큰). 정지 이유는 `state.json`의 값을 그대로 쓰므로 L4b의 `budget`/`interrupted`도 따로 손대지 않고 알림에 나온다. `JUNEES_NOTIFY_EACH_SESSION=1`이면 세션마다 한 줄. `allowed_mentions: {"parse": []}`, 2000자 제한, 타임아웃 10초, 리다이렉트 안 따라감. 실패는 경고만 하고 종료 코드는 그대로. URL은 출력하지 않고 호스트만 보여 주며, 세션의 bash와 하네스 git에도 넘기지 않는다. 정지를 기록하기 전에 실패한 run(더러운 작업 트리 등)도 `run failed: <오류>` 한 번을 보낸다. 세션 알림은 상태(그 세션의 토큰, 마지막 세션이면 정지 기록)를 저장한 뒤에 보낸다. 웹훅은 https만 받고(평문 http는 루프백만), 바뀌는 텍스트는 인라인 코드로 감싸 마크다운이 적용되지 않게 한다
- 보안: junees는 시작할 때 `prctl(PR_SET_DUMPABLE, 0)`으로 dump 불가 프로세스가 되어, bash가 `/proc/$PPID/environ`(또는 더 위 조상)에서 숨긴 API 키와 웹훅 URL을 읽지 못한다(PR #1부터 있던 우회로)

### 구독 백엔드 (Claude Code CLI)
- `task init`/`task run`에 `--backend claude-code`(또는 `JUNEES_BACKEND`). 세션을 공식 `claude` CLI가 실행하고, 사용자가 자기 구독으로 직접 로그인한다(`claude` 실행 후 `/login`, 또는 `claude setup-token`). Junees는 Claude 자격 증명을 읽거나 저장하거나 보내지 않고 `claude`를 실행만 한다(약관상 허용되는 길). `ANTHROPIC_API_KEY`는 필요 없고, `claude`의 환경에서 인증 우선순위상 구독보다 앞서는 변수(API 키와 토큰, `ANTHROPIC_BASE_URL`, `CLAUDE_CODE_USE_*` 클라우드 제공자와 그 키, `ANTHROPIC_PROFILE`과 federation 변수)를 지운다. 설정 파일의 `apiKeyHelper`/`env`는 시작할 때와 세션마다 `claude auth status --json`의 `authMethod`가 `claude.ai`/`oauth_token`인지 확인해 막는다
- 토큰 보호: 세션마다 `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`을 켜서 Claude Code가 Bash 명령의 환경에서 `CLAUDE_CODE_OAUTH_TOKEN` 등 자격 증명을 지우게 한다(Linux에서는 bubblewrap 필요, 없으면 시작 경고). 사용자가 끄면 그대로 넘기고 시작 경고
- 세션: `claude -p ... --output-format stream-json --verbose --append-system-prompt <규칙과 상태> --permission-mode acceptEdits --permission-prompts none --tools/--allowedTools Read,Edit,Write,Glob,Grep,Bash --setting-sources user --strict-mcp-config --max-turns N --disallowedTools <L4a 핵심 규칙>`. `--dangerously-skip-permissions`는 쓰지 않는다. 시작 전에 `claude --version`(2.1.259 이상) 확인, 로그인 실패(마지막 모델 호출의 인증 오류나 `auth status`)면 안내와 함께 `error` 정지와 알림
- `mark_feature_passing`이 없으므로 세션 뒤 하네스가 통과하지 않은 기능의 verify를 직접 실행해 기록한다(취소, 로그인 실패면 건너뜀, 시간 예산을 verify마다 확인). 나머지 하네스 규칙(목록 되돌리기, 체크포인트, 정지 조건, 재검증, 크래시 복구, run.log, 알림)은 그대로
- stream-json의 응답별 usage로 세션 중 예산을 확인하고(넘으면 SIGINT, 유예 뒤 SIGKILL), 끝나면 `result`의 `modelUsage`/`usage`를 누적. 취소도 같은 방식이고 `interrupted`. 정지할 때는 SIGINT 전에, 그리고 SIGKILL 전에 한 번 더 `claude`의 자손 프로세스(별도 세션으로 뜬 Bash 명령 포함)를 SIGSTOP으로 멈춘 뒤 SIGKILL한다. 원본 출력은 `.junees/sessions/<이름>.jsonl`(git 제외), 비용 추정과 Claude Code 세션 id는 run.log
- 구독 사용 한도(#20): 끝나지 못한 세션이 `rate_limit_event`(`status: rejected`)로, 또는 429(마지막 모델 호출의 `rate_limit` 오류나 `api_error_status: 429`인 `result`)와 errors 문서의 한도 문구(`You've hit your ... limit`)로 끝나면 `limit`으로 정지(한도 문구 없는 429는 서버의 일시 제한일 수 있어 `error`)(종료 코드 0, 실패 아님). 리셋 시각은 거절 이벤트의 `resetsAt`(unix 초)이 있을 때만 `state.json`의 `stop.resets_at`에 남기고, Claude Code의 메시지는 `detail`. 정지 문장(리셋 시각과 "리셋 뒤 `junees task`를 다시 실행" 안내)이 `task status`(JSON `resets_at`), run.log, 알림에 나온다. 그 세션의 작업은 다른 세션처럼 verify, 체크포인트 커밋을 거친다. 자동으로 기다렸다 이어 가지는 않는다
- 설정 파일 보호: `--disallowedTools` 끝에 `$JUNEES_HOME/config.toml`(`..`, 링크를 푼 경로)의 `Read(//<경로>)`, `Edit(//<경로>)`(gitignore 특수 문자 이스케이프)와, 폴더가 저장소와 겹치지 않으면 `Read(//<폴더>/**)`, `Edit(//<폴더>/**)`, 폴더 이름을 쓰는 Bash 명령 규칙(`Bash(*<폴더>*)`, `~/`, `$HOME/`, `$JUNEES_HOME` 형태)을 붙인다. 파일을 직접 여는 스크립트, 실행 중에 만든 경로, 더 위 폴더를 다루는 명령은 막지 못한다
- 한계: Claude Code 권한 규칙은 쓰인 단어만 맞추므로 Junees bash 정책보다 약하다(`/usr/bin/sudo`, `git -C . push --force`, `bash -c`, fork bomb 등). 정지 전에 `claude`가 스스로 죽으면 그 명령은 남는다. 실제 `claude`로는 테스트하지 않았다(가짜 실행 파일로 검증)

### 사용법 단순화 (Hermes처럼)
- `junees` 하나만 외우면 되게: `junees`(대화), `junees "질문"`(한 번만, `-p`와 같음), `junees -c`, `junees task "목표"`(init + run을 한 프로세스에서), `junees task`(이어서 run), `junees status`, `junees setup`. 예전 플래그와 `task init/run/status`는 그대로 동작하고 `--help`의 `Advanced` 절로 옮겼다
- 설정 파일 `$JUNEES_HOME/config.toml`(0600, 폴더 0700): 평평한 TOML 부분집합을 직접 파싱(의존성 없음). 키마다 환경 변수 하나에 대응하고, `Settings`가 실행 중 변경(`/model`, `/backend`) -> 환경 변수 -> 파일 순서로 찾아 기존 `from_lookup` 이음새에 넘긴다. 설정 파일 키는 표(`KEYS`)에 있는 것만 받아서 Junees가 원래 읽지 않는 변수(`ANTHROPIC_TOKEN` 등)는 파일로도 생기지 않는다. 모델의 도구는 이 파일을 건드리지 못한다(`src/tools/settings_file.rs`): `read_file`/`write_file`/`edit_file`은 경로를 풀어서(`..`, 심볼릭 링크, 하드 링크) 거절하고, `bash` 정책은 파일을 이름(글롭, 중괄호 포함)으로 가리키는 명령과 `$JUNEES_HOME` 폴더를 `ls`/`cd`/`stat` 등 말고 통째로 다루는 명령을 `JUNEES_ALLOW_DANGEROUS=1`이어도 막는다. bash 쪽은 차단 목록이라 다른 변수, 실행 중에 만든 경로, 더 위 폴더(`grep -r api_key ~`)를 통한 접근은 통과한다
- 처음 실행 마법사(파일도 `ANTHROPIC_API_KEY`도 없고 stdin/stderr가 터미널일 때, 또는 `junees setup`): 구독(claude-code) 또는 API 키, 구독이면 task 백엔드의 `claude --version`/`auth status` 검사를 그대로 써서 로그인 방법(Linux면 bubblewrap)을 안내한다(대화도 구독으로 돌므로 API 키는 묻지 않는다, 아래 대화 모드 구독 백엔드). 키는 termios echo를 끄고 입력받고 다시 출력하지 않는다. 모델, 작업 기본 예산(2h, 토큰 상한 선택). 마법사 입력은 대화와 같은 `SharedLines`로 읽고 Ctrl-C는 echo를 되돌린 뒤 취소한다
- 대화 안 슬래시 명령: `/task [목표]`(같은 프로세스에서 init + run, 끝나면 원래 폴더로 돌아옴, Ctrl-C는 `junees task`처럼 세션을 마무리하고 멈춤), `/status`, `/sessions`(번호로 골라 이어 가기), `/new`(`/reset`), `/model [이름]`, `/backend [api|claude-code]`. `/model`과 `/backend`는 이 실행에만 적용(파일은 `junees setup`만 바꿈)
- 남은 것: 모델이 bash로 설정 파일의 키를 읽는 것을 막기 (대화 모드 구독은 아래 단계)

### 대화 모드 구독 백엔드 (claude-code로 대화)
- `backend = claude-code`(설정 파일, `JUNEES_BACKEND`, `/backend claude-code`)이면 대화, `junees "질문"`/`-p`, `-c`도 `claude`로 돌린다. API 키는 필요 없다
- task 전용이던 `src/task/claude_code.rs`의 공통 부분(백엔드 설정, `--version`/`auth status` 확인, 환경 정리와 `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB`, 세션 실행과 예산/취소, 프로세스 그룹과 자손 종료, stream-json 읽기, 로그인 실패/사용 한도 판정, deny 규칙)을 `src/claude_code/`로 옮겼다. task 쪽은 인자(`acceptEdits`, 시스템 프롬프트)와 실행만 남았고 동작과 기존 테스트는 그대로다
- 한 턴 = 지금 폴더에서 `claude -p --output-format stream-json --verbose --include-partial-messages --permission-mode default --permission-prompts none --tools/--allowedTools Read,Edit,Write,Glob,Grep,Bash --setting-sources user --strict-mcp-config --max-turns N [--resume <id>] [--model M] --disallowedTools <규칙>`. 두 번째 턴부터 앞 턴이 알려 준 `session_id`를 `--resume`으로 넘긴다(headless 문서 Continue conversations, cli-reference `--resume`). 입력은 표준 입력으로 쓰고 닫는다(headless 문서 "Non-interactive mode reads stdin"): 인자 하나의 128 KiB 한도(E2BIG)와 `-`로 시작하는 입력이 옵션으로 읽히는 문제를 피한다
- 권한: `--permission-mode default`(cli-reference: `manual`은 별칭)에 task와 같은 허용/거절 규칙. 확인이 필요한 호출은 `--permission-prompts none`으로 거절되고, `permission_denied` 이벤트(도구 이름, 이유)와 `result.permission_denials`(이벤트로 못 본 것)를 화면에 보여 준다. `--permission-prompt-tool`(MCP)로 Junees 승인 질문을 붙이는 것은 문서상 가능하지만(stdio MCP 서버 구현, 대화 프로세스와의 통로, `--permission-prompts host`, 이때 거절 이벤트 없음, MCP 연결 대기) 후속으로 미뤘다
- 출력: `stream_event`의 텍스트 조각을 #18 스트리밍처럼 찍고 같은 응답의 완성 블록은 다시 찍지 않는다. `api_retry`면 `Retrying`으로 끊긴 조각을 버린다. 도구는 `-> Tool`/`<- Tool ok`. `/usage`는 턴들의 토큰, 턴 수, Claude Code 세션 id. 이어 간 턴은 `result` 합계에 이전 실행분이 들어 있어서(headless 문서) 응답별 합만 센다
- 세션 기록 형식 5: meta의 `backend: "claude-code"`와 턴마다 `claude_turn { claude_session, input, text, usage, end }`. 재생하면 마지막 Claude Code 세션 id와 턴 수, 사용량이 복원되고 메시지 기록은 비어 있다(Claude Code가 들고 있음). 형식 4 바이너리가 빈 API 대화로 잘못 열지 않도록 `FORMAT`을 5로 올렸다. `-c`는 지금 백엔드의 세션만 고르고, `--resume`/`/sessions`로 다른 백엔드 세션을 고르면 `/backend`로 바꾸라는 오류. Junees 쪽 압축(L2)은 이 백엔드에서 쓰지 않는다
- 슬래시 명령: `/compact`, `/context`는 Claude Code가 컨텍스트를 스스로 관리한다는 안내(문서의 `-p` 지원 명령에 없음). `/model`은 `--model`로 전달(`JUNEES_CLAUDE_MODEL` 덮어씀). `/backend`는 대화와 `/task`를 함께 바꾸고 대화를 바꾸면 새 세션
- 한도: 턴이 사용 한도로 끝나면 #26 판정 그대로 리셋 시각과 함께 알리고 턴을 끝낸다(`-p`는 종료 코드 1). Ctrl-C: claude와 자손을 끝내고 턴을 `interrupted`로 기록, 다음 입력은 같은 세션을 이어 간다
- 마법사: 구독을 고르면 대화도 구독으로 된다고 안내하고 API 키를 묻지 않는다
- 한계: 실제 `claude`로는 테스트하지 않았다(가짜 실행 파일로 검증). Claude Code가 세션 id를 알리기 전에 끊긴 첫 턴은 이어 갈 수 없다

### 스킬 (로드맵 4단계 B)
- 저장: `$JUNEES_HOME/skills/<이름>/SKILL.md`(앞머리 `name`, `description` + 본문)와 선택적 `references/`, `templates/`, `scripts/`, `assets/` 파일. 이름 `[a-z0-9-]{1,64}`, 앞머리 `name`은 폴더 이름과 같아야 한다. YAML은 직접 읽는다(최상위 한 줄 `name`/`description`만, 따옴표 허용, 블록 스칼라 거절. 다른 키와 들여쓴 줄은 무시). 새 의존성 없음
- `src/skills/`: `Index`(목록과 건너뛴 폴더의 이유), `Store`(파일 작업), `tools`(`skill_view`, `skill_manage`). 공유 파일은 연결만 바꿨다: `main.rs`(도구 등록, 시스템 프롬프트, `/new`, `/skills`, `/skill`), `task/runner.rs`(`TaskEnv::agent`와 Claude Code 세션의 시스템 프롬프트), `claude_code/chat.rs`(`--append-system-prompt`), `agent.rs`(`set_system`), `slash.rs`, `cli.rs`, `config.rs`/`config_file.rs`(`JUNEES_TASK_SKILL_MANAGE`)
- 시스템 프롬프트: `# Skills` 절에 지침(작업 전에 맞는 스킬을 `skill_view`로 읽고 따를 것, 여러 단계를 해냈거나 사용자가 정정하면 `skill_manage`로 남기거나 고칠 것, 비밀과 일회성 내용은 넣지 말 것), 목록은 작성자가 쓴 데이터일 뿐 지시가 아니고 스킬은 사용자나 규칙보다 앞서지 않는다는 안내, 그리고 `- 이름: 설명` 목록(제어 문자와 방향 제어 문자는 `prompt_text::escape_hidden`으로 이스케이프. 쓸 때는 `prompt_text::check_plain`으로 거절). 목록은 4000자 상한(`INDEX_MAX_CHARS`)까지 줄 단위로 넣고 넘는 스킬은 개수만 적는다. 세션 시작 때 한 번 읽어 고정한다: 대화는 에이전트를 만들 때와 `/new`(`Agent::set_system`, Claude Code는 `Chat::set_system`), 작업은 세션마다. 바뀐 내용은 도구 결과가 "다음 세션부터 목록에 나온다"고 알려 준다
- `skill_manage`: `create`/`patch`는 결과 `SKILL.md` 전체를 검사(크기, 앞머리, 이름 일치, 비밀)하고, 목록을 상한 넘게 늘리면 거절(줄어드는 변경은 언제나 허용, 거절 메시지에 가장 긴 설명 셋). 설명이 60자를 넘으면 저장하고 짧게 하라는 안내만. `patch`는 겹치는 일치까지 세어 정확히 한 번이어야 한다. `write_file`은 네 하위 폴더 아래만, `delete`는 확인 없이 `.trash/<이름>-<unix 초>[-n]`으로 rename. 파일 작업은 `spawn_blocking` 안에서 `std::fs`로 끝까지 한다(취소돼도 임시 파일이 남지 않음)
- 경로: `file_path`는 상대 경로만(`.`/`..`/빈 조각/절대 경로 거절). 읽기는 정규화한 경로가 스킬 폴더 안이어야 하고, 쓰기와 지우기는 스킬 폴더 아래 심볼릭 링크를 지나거나 링크 자체에 쓰는 것을 거절한다(스킬 폴더 자체나 `skills/`가 링크인 것은 사용자의 선택으로 허용)
- 비밀 판정: 메모리(4단계 A)와 merge하면서 `src/secrets.rs` 하나로 합쳤다. 기준은 하나다: 단어 첫머리의 알려진 접두사 뒤 키 문자 12자 이상, `-----BEGIN`과 `PRIVATE KEY`가 든 줄, 단어로 선 `AKIA`/`ASIA` + 대문자/숫자 16자, 토큰 문자열 안의 32자 이상 hex(한 글자 반복은 통과, 40/64자 소문자 hex는 옆 단어가 `commit`/`sha`/`커밋` 등일 때만 통과), 대소문자와 숫자가 섞인 32자 이상 토큰 문자열(`/`, `.`에서 끊김). 스킬의 48자 hex(40자 SHA 무조건 통과)와 64자 base64 기준은 버렸다: 32자, 40자 hex 토큰을 쓰는 서비스가 있고, 이름 붙은 해시는 예외로 충분해서다. 메모리 쪽은 `AWS_ACCESS_KEY_ID=AKIA...`(소문자가 없어 섞인 토큰 규칙에도 안 걸림)를 놓치던 것을 고쳤다
- 작업 모드: 목록과 `skill_view`는 늘, `skill_manage`는 `JUNEES_TASK_SKILL_MANAGE=1`(`task_skill_manage`)일 때만 등록한다(없을 때 부르면 `unknown tool`). 지침도 "이 세션에서 스킬은 읽기 전용"으로 바뀐다
- claude-code 백엔드: 대화, `/new`, 작업의 계획/작업 세션 모두 메모리 절 다음에 목록을 붙여 한 `--append-system-prompt` 인자로(`prompt::claude_append`. 둘 다 비면 인자 없음). `settings_rules`가 `$JUNEES_HOME` 전체의 Read/Edit를 거절하므로 Claude Code는 스킬 파일을 읽을 수 없고, 목록에 그렇다고 적는다. 메모리를 모두 8000자로 채우고 목록까지 꽉 채운 최악의 경우(4바이트 문자)도 128 KiB 한도 아래인지 테스트로 확인한다
- 남은 것: 여러 Junees 프로세스가 같은 스킬을 동시에 고치면 마지막 쓰기가 이긴다(잠금 없음). 하위 폴더(카테고리)나 Hermes 스킬 형식의 메타데이터는 읽지 않는다

### 디스코드 게이트웨이 (로드맵 5단계)
- `junees gateway`(별칭 `junees discord`): 새 모듈 `src/gateway/`에 두고 기존 파일은 연결만 바꿨다: `main.rs`(명령, 백엔드별 Engines, 시그널), `cli.rs`(명령과 도움말), `config_file.rs`(`discord_*` 키), `tools/mod.rs`(`JUNEES_DISCORD_TOKEN`을 `SECRET_ENV_VARS`에), `secrets.rs`(디스코드 봇 토큰 모양), `setup.rs`(선택 단계), `lib.rs`
- 의존성: 봇 프레임워크 대신 `tokio-tungstenite`(rustls + webpki roots, reqwest와 같은 rustls 0.23)와 `futures-util`(Sink/Stream)만 더했다. Gateway v10 JSON, 압축과 샤딩 없음
- 연결(`shard.rs`): Get Gateway Bot의 주소를 캐시해 재사용, Hello -> 지터 곱한 첫 하트비트 -> 간격마다, ACK 누락이면 4000으로 닫고 RESUME(`resume_gateway_url`, `session_id`, `seq`), op 1 요청엔 즉시 하트비트, op 7과 재연결 가능한 닫힘은 RESUME, op 9 `false`면 1~5초 뒤 처음 주소로 IDENTIFY, 4007/4009는 새 세션, 4004/4010~4014는 끝(4014는 MESSAGE CONTENT INTENT 안내). 재연결 대기 1초부터 두 배씩 120초까지, Ready/Resumed에 초기화. 연결 실패(거절, 시간 초과, 핸드셰이크)에는 RESUME 정보를 남기고 다시 RESUME(세션은 4007/4009와 op 9 `false`에서만 버림), `resume_gateway_url`에 3번 잇달아 실패하면 처음 주소로 RESUME
- REST(`rest.rs`): 경로(메서드 + 채널 id)별로 `X-RateLimit-Remaining: 0`이면 `Reset-After`까지 대기, 429는 `retry_after`(전역이면 모든 경로) 대기 후 재시도 5번, 네트워크 오류/5xx 3번. `X-RateLimit-Bucket` 묶음은 쓰지 않음. 모든 메시지에 `allowed_mentions: {parse: []}`, 그리고 재시도해도 두 번 올라가지 않게 `nonce`(메시지마다 무작위, 재시도는 같은 값) + `enforce_nonce: true`. 오류는 경로만, URL은 `without_url`
- 보안: 허용 사용자 목록이 비면 시작 거부. 토큰은 `Token`(Debug 숨김, Display 없음), 헤더는 sensitive. API URL은 https(루프백만 http), Gateway 주소는 wss(루프백만 ws). 다른 사용자의 메시지는 로그에 id만 한 번. `!memory`는 서버 채널에서 개수와 크기만, 내용은 DM에서만
- 대화: 채널마다 작업자 하나(대기열, `!stop`은 epoch를 올려 대기열을 버리고 Cancel), 동시 실행은 Semaphore(`discord_parallel`, 기본 2). 에이전트와 Claude Code 대화의 future가 `Send`가 아니어서(Agent가 `&self`를 await 너머로 잡음) 채널들은 `LocalSet` 한 스레드에서 돈다. 그래서 `Gateway::run`은 `block_on`으로 돌려야 한다(테스트는 전용 스레드와 current_thread 런타임). Agent를 `Send`로 바꾸는 것은 다른 작업과 겹치는 `agent.rs` 변경이라 하지 않았다
- 세션: 보통 세션 기록을 쓰고 채널 -> 세션 id 색인(`$JUNEES_HOME/gateway/discord-sessions.json`)만 더했다. 처음에는 `session.rs`와 세션 형식을 바꾸지 않았다. 그 뒤 #34로 채널 세션의 meta에 `source: "discord"`와 `channel: "<id>"`를 남기고(`SessionWriter::create_for_channel`), `find_latest`(`-c`)와 `list_recent`(`/sessions` 번호 목록)가 건너뛴다. `/sessions`는 `list_channel_sessions`로 번호 없이 보여 주기만 한다. 형식 번호는 올리지 않았다: 이전 Junees는 meta의 모르는 필드를 무시하고 대화를 그대로 읽으므로, 그 세션을 `-c` 후보에 넣는 것 말고는 달라지지 않는다. 다른 백엔드의 세션, 지워지거나 깨진 세션이면 새로 시작하고 이유를 `!status`에. 다른 Junees가 연 세션(잠김)이나 디스크 오류면 색인을 그대로 두고 메시지를 `(not run)`으로 돌려보낸 뒤 다음 메시지에 다시 시도. 한 `$JUNEES_HOME`에 게이트웨이 하나(`gateway/lock` flock, 두 번째는 시작 거부)
- 출력: 메시지 편집 스트리밍 대신 완성된 텍스트 블록마다 보낸다(레이트 리밋, 재시도 시 지울 텍스트). 도구 호출은 다음 텍스트나 질문 전에 한 코드 블록으로. 2000자 나누기는 UTF-16 길이로, 다시 여는 펜스는 펜스와 짧은 언어만, 같은 줄에서 닫히는 펜스는 블록이 아님
- 승인: `Ask`를 채널용으로(`ask.rs`). 질문은 작업자의 출력 순서를 거쳐(도구 줄 뒤) 나가고, 답 슬롯이 차 있으면 그 채널의 다음 비명령 메시지가 답이다(멘션 없어도). `y`/`n`/`n 이유`/`a`/그 밖은 이유로 거절, 시간 초과는 거절. claude-code 백엔드는 질문 없음
- 종료: SIGINT/SIGTERM이면 채널 턴을 취소(기록)하고 작업자를 30초까지 기다린 뒤 1000으로 닫는다
- 테스트: `tests/discord_gateway.rs`(가짜 Gateway/REST, 실제 에이전트 + 가짜 API로 세션 이어 가기와 승인), 모듈 단위 테스트(설정, 나누기, 답 읽기, 명령, 토큰 모양)
- 미룬 것: `!task`(작업 모드가 프로세스 cwd를 바꾸고 저장소당 하나라 게이트웨이의 동시 채널과 따로 설계 필요), 슬래시 명령 등록, 첨부 파일, 봇이 스레드를 만드는 것, 메시지 편집 스트리밍. 실제 디스코드로는 확인하지 않았다

### 서브에이전트 (로드맵 6단계)
- 새 모듈 `src/subagent/`(`mod.rs`, `run.rs`, `tests.rs`)에 두고 공유 파일은 연결만 바꿨다: `agent.rs`(delegate 실행, 공유할 필드를 `Arc`로), `tools/mod.rs`(`ToolRegistry`가 `Arc<dyn Tool>`을 들고 `without`으로 일부를 빌려줌), `session.rs`(`Journal::file`, `SessionWriter::create_sub`, `subagent_usage`), `approval.rs`(`ToolGate::check_for`), `config.rs`/`config_file.rs`(`JUNEES_SUBAGENTS`, `JUNEES_SUBAGENT_MAX_TURNS`, `JUNEES_SUBAGENT_MAX_TOKENS`), `main.rs`/`gateway/engine.rs`/`task/runner.rs`(등록, 프롬프트 한 줄, 진행 줄 표시), `Cargo.toml`(이미 쓰던 `futures-util`에 `alloc` 기능만, 새 의존성 없음)
- 실행 위치: `delegate`는 보통 도구(`Tool::run`, `Send` future)가 아니라 에이전트 루프가 직접 돌린다(`Agent::with_delegate`는 모델에 보일 도구 정의만 등록한다). Agent future는 `Send`가 아니므로(위 게이트웨이의 LocalSet) 자식을 spawn하지 않고 부모 future 안에서 `buffered(parallel)`로 함께 poll한다. 그래서 대화(멀티스레드 런타임의 `block_on`), 게이트웨이(LocalSet), 작업 모드에서 같은 코드가 돈다. 루프 안이라 부모의 provider(`Arc`), 도구, 취소, 승인 게이트(`Arc<dyn ToolGate>`), 한도(`Arc<Mutex<Limit>>`), 세션 기록 경로를 그대로 쓴다. `/model`로 바꾼 provider도 자식이 따른다
- 취소: 다른 도구 호출은 취소 신호와 select해서 future를 버리지만 delegate는 버리지 않는다. 자식이 같은 `Cancel`을 보고 스스로 멈춰 자기 기록에 `cancelled` 결과를 남긴 뒤 돌아오므로, 부모는 결과를 기록하고 `Cancelled`로 끝난다
- 예산: 자식의 `Limit` = 자기 토큰 상한, 그다음 부모의 `Limit`(부모가 호출 전까지 쓴 토큰 + 모든 자식의 지금까지 토큰). 자식마다 모델 호출 전과 끝났을 때 공유 표에 사용량을 적는다(돌고 있는 자식의 마지막 호출 몫은 그 자식의 다음 확인 때 반영). 끝나면 합계를 부모 기록에 `subagent_usage`(형식 6, 컨텍스트 크기에는 쓰지 않음)로 남겨 `/usage`, 작업 상태의 토큰, 작업 예산에 들어간다. 자식이 부모 예산으로 멈추면 부모는 다음 모델 호출 전 확인에서 멈춘다
- 승인: `ToolGate::check_for(agent, tool, input)`(기본 구현은 `check`). `Approval`은 이유 맨 앞에 `asked by subagent [n] <goal>`을 넣는다. 자식 게이트(`ChildGate`)는 부모 게이트를 함께 쓰므로 "항상 허용"도 함께 쓴다. 다른 자식의 진행 줄은 질문 중에도 표준 오류에 찍힌다. 처음에는 게이트 전체를 `tokio::sync::Mutex`로 잠근 채 물어서, 한 자식이 답을 기다리는 동안 다른 자식의 모든 도구 호출(묻지 않아도 되는 것까지)이 멈췄다(#37). 지금은 `ToolGate::check`가 `&self`를 받고 `Approval`이 안에서 나눈다: 물을지 판단과 "항상 허용" 확인은 잠금 없이(허용 목록만 짧은 `std::sync::Mutex`), 질문만 묻는 쪽끼리 `tokio::sync::Mutex`로 하나씩. 차례를 기다린 질문은 그동안 나온 "항상 허용"을 다시 확인한다. 테스트: 자식 1이 답을 기다리는 동안 자식 2의 `echo`가 실행되고 끝나는지(수정 전에는 5초 시간 초과로 실패), 동시에 기다린 두 질문 중 하나만 묻는지
- 진행: `Event::Subagent { index, line }` 한 줄(도구 호출, 오류 결과, 경고, 압축, 시작과 끝). main은 `  [n] ...`, 게이트웨이는 도구 줄. 자식의 텍스트와 thinking은 보내지 않는다. 모델이 쓴 goal과 입력은 `escape_hidden`을 거친다
- 자식 기록: 부모 기록 파일 옆 `<id>/sub-<n>.jsonl`(번호는 그 폴더의 가장 큰 번호 다음, 파일은 첫 항목 때 만듦, flock, 0600/0700). meta는 부모의 cwd와 모델, id는 `<부모 id>/sub-<n>`. `session_files`는 `sessions/` 바로 아래 `.jsonl`만 보므로 목록과 `-c`에 섞이지 않는다
- 테스트: 첫 메시지로 대화를 고르는 Router provider(지연, 동시 호출 수 측정)로 병렬 상한과 과제 순서, 새 기록과 도구 제외, context, 재귀 금지, 부모 한도와 자식 토큰/턴 상한, 취소와 자식 기록, 기록 위치/권한/번호/목록 제외, 승인 공유, 결과 크기(한글), 입력 오류, 설정(`src/subagent/tests.rs`). `task::runner`에는 작업 토큰 예산이 자식 토큰을 세는 테스트, `approval`에는 질문의 서브에이전트 표시 테스트. 취소 select, 도구 제외, 병렬, 부모 한도, 사용량 기록, 게이트 공유를 하나씩 되돌리는 변이 스크립트로 각각 테스트가 실패하는 것을 확인했다
- 미룬 것: claude-code 백엔드(Claude Code에 자체 Task 도구가 있다), 같은 파일을 동시에 고치는 자식 사이의 잠금, 자식 기록 이어 가기, 호출마다 자식 한도를 정하는 인자. 실제 API로는 돌려 보지 않았다

### MCP 클라이언트 (로드맵 6단계 A)
- 명세: MCP 2026-07-28(현재 판, 2025-11-25 다음). 이 판은 `initialize`/`notifications/initialized`를 없애고 요청마다 `_meta`(`io.modelcontextprotocol/protocolVersion`, `clientInfo`, `clientCapabilities`)를 싣고 `server/discover`를 더했다(changelog Major 2, 3). 스펙 문서의 "`initialize` -> `notifications/initialized` -> `tools/list`" 순서는 이전 판의 것이라, 명세가 권하는 dual-era 클라이언트로 구현했다: stdio에서 `server/discover`로 탐색하고, 결과나 `UnsupportedProtocolVersion`(-32022)이면 modern, 그 밖의 오류나 시간 초과면 legacy `initialize`로(stdio 바인딩 Backward Compatibility: 특정 오류 코드에 기대지 말 것). 탐색 5초가 지나면 `initialize`를 보내되 탐색 답을 계속 받는다(느린 modern 서버). 탐색에 프로세스가 끝나면 다시 띄워 바로 `initialize`

### 예약 작업 (로드맵 6단계 2차 A)
- 새 모듈 `src/cron/`(`tz.rs`, `schedule.rs`, `store.rs`, `deliver.rs`, `output.rs`, `run.rs`, `daemon.rs`, `cli.rs`, `command.rs`, `mod.rs`)에 두고 공유 파일은 연결만 바꿨다: `lib.rs`, `cli.rs`(`Command::Cron`, 도움말), `main.rs`(명령 연결, 처음 실행 마법사 제외, `/cron`), `slash.rs`(`/cron`), `gateway/bot.rs`(`!cron`, 도움말), `config_file.rs`(`timezone`, `cron_max_time`, `cron_max_tokens`), `tools/settings_file.rs`(데이터 폴더 `cron`)
- 시간대: 의존성 없이 시스템의 TZif 파일(RFC 8536, 버전 1~4)을 읽는다. 64비트 블록의 전환 시각과 오프셋, 그 뒤의 시각은 꼬리의 POSIX TZ 규칙(`Mm.w.d`, `Jn`, `n`, `<+09>` 이름, 남반구)으로 계산한다. 현지 시각 -> UTC는 하루 앞뒤와 그 시각의 오프셋을 후보로 맞는 것 중 이른 것(두 번 오는 시각은 처음), 맞는 것이 없으면(건너뛴 시각) 앞 오프셋으로 간격만큼 뒤. 이름은 `zoneinfo` 아래 경로만(`..`, 절대 경로 거절), 테스트는 `tests/fixtures/America_New_York.tzif`(시스템 파일 사본)와 POSIX 규칙 둘 다로. `chrono-tz`(DB를 바이너리에 넣음)나 `jiff` 대신 이렇게 한 이유: 필요한 것은 오프셋 조회와 현지 시각 변환뿐이고, 시스템 DB가 OS 업데이트로 최신이 된다
- 일정(`schedule.rs`): `Schedule`(`every`는 추가한 시각 기준 간격, `in`과 ISO는 `once`, `daily`, `weekdays`, 5필드 cron 식은 쓴 그대로 저장하고 쓸 때 다시 읽음). `next_after(t)`는 t보다 엄격히 뒤의 첫 시각. cron 식은 날짜를 하루씩(최대 9년, 2월 29일) 보고 맞는 날의 시/분을 차례로 UTC로 바꿔 처음으로 t보다 뒤인 것을 고른다. 추가할 때 다음 실행이 없으면 거절
- 저장(`store.rs`): `jobs.json` `{format: 1, jobs: [...]}`, 작업은 id, name, schedule, timezone(추가할 때의 시간대 이름, 이름으로 다시 찾을 수 있을 때만), text(입력 그대로), prompt, dir(절대), deliver(`local`/`webhook`/`discord:<id>` 문자열), paused, created_at, next_run, last(run_id, due, started_at, finished_at, status, note, output, session, tokens, delivery_error). 쓰기는 `jobs.lock` flock(`flock::try_exclusive`를 10초까지 반복) 아래 임시 파일 + rename + 폴더 fsync. 더 새 format, 다른 사용자 소유, 그룹/기타 쓰기 가능, 일반 파일이 아닌 것은 거절
- 실행(`run.rs`, `command.rs`): `junees cron run <id>`가 실행 하나다. `last`를 `running`으로 적고, 작업 폴더로 `set_current_dir`한 뒤 `Engine`(api: `ApiEngine`, claude-code: `ClaudeEngine`)으로 돌리고, `cron::finish`가 출력 파일, 전달, `last` 기록을 한다. api 엔진은 `-p`처럼 게이트 없음, MCP 시작, 서브에이전트, `memory::Mode::ReadOnly` + `skills::register(.., false)` + `skills::Mode::ReadOnly`, 새 세션, `Agent::with_limit`(토큰과 시간) + 시간이 되면 `Cancel`(`Deadline`). 답은 마지막 도구 호출 뒤의 텍스트(실패해도 그때까지의 텍스트). 실패 이유: 시간 초과(취소 + 시간 지남), 토큰 한도, 턴 한도, 중단(시그널), 그 밖의 오류
- 데몬(`daemon.rs`): `Clock`(시스템/가짜)과 `Launcher`(프로세스/가짜) 트레이트. 매 분 0초 `tick(now)`가 때가 된 작업의 `next_run`을 `next_after(now)`로 먼저 옮겨 저장하고(그래서 밀린 반복 작업은 한 번만, 시작 중 죽어도 두 번 돌지 않음) `Run`/`Missed`(한 번짜리가 10분 넘게 늦음)/`Busy`(이전 실행이 아직 돎)를 돌려준다. 실행은 `current_exe() cron run <id> --run-id <r> --due <t>`를 `/`에서, 자기 프로세스 그룹으로. 끝나면 `last.run_id`가 그 실행이고 `running`이 아니어야 하며, 아니면 데몬이 실패로 기록하고 전달한다. 시간 한도 + 60초면 SIGINT, 30초 뒤 SIGKILL. 데몬 하나(`cron/daemon.lock`). 게이트웨이 안에서 돌리지 않은 이유는 [automation.md](automation.md#예약-작업)의 예약 작업 절
- 전달(`deliver.rs`): 디스코드는 `gateway::rest::Rest`를 `discord_token`과 `JUNEES_DISCORD_API_URL`만으로 만든 `DiscordConfig`로 재사용(허용 사용자 목록 불필요), `split_message`로 다섯 메시지까지. 웹훅은 `Notifier::send`. 제목 줄의 이름과 이유는 `escape_hidden` + 백틱을 `'`로
- 테스트: 단위(`src/cron/*`: 시간대 오프셋/건너뛴 시각/두 번 오는 시각/POSIX 규칙/이름 탈출/깨진 파일, 일정 경계와 DST와 잘못된 식 25가지, 저장 권한/잠금 대기/거절, 출력 파일과 100개 유지, 가짜 HTTP로 디스코드와 웹훅 전달, Scripted provider로 실행(읽기 전용 도구, 토큰 한도, 시간 한도, 중단), 가짜 시계와 가짜 실행기로 따라잡기/놓침/바쁨/매 분 틱/결과 없이 끝난 실행), 통합 `tests/cron.rs`(바이너리 add/list/run/pause/resume/rm, 가짜 API와 가짜 디스코드 REST, 데몬이 때가 된 작업을 자식 프로세스로 실행하고 실패를 전달). 시간대 변환, 따라잡기, 놓침 판정, 결과 확인, 권한 검사, 읽기 전용 스킬, Vixie 규칙, 메시지 상한, 데이터 폴더 보호를 하나씩 되돌리는 변이 스크립트로 각 테스트가 실패하는 것을 확인했다
- 시간대를 작업에 저장하는 이유: 바이너리 스모크에서 `America/New_York`으로 추가한 작업을 `Asia/Seoul` 설정으로 보면 다음 실행 시각(뉴욕 기준으로 계산)과 설명(서울)이 어긋났다. 셸의 `TZ`와 서비스 환경의 시간대가 다른 흔한 경우도 같다. 이제 계산, 목록, 출력 파일 모두 작업의 시간대를 쓰고 설정은 이름 없는 시간대일 때의 대체값이다
- 리뷰 반영(#39): 예약 실행 세션은 meta `source: "cron"`, `channel: <작업 id>`(#38의 채널 세션과 같은 방식)라 `-c`와 `/sessions` 번호 목록에서 빠진다. 새 모듈 `src/tools/self_command.rs`가 bash 명령 안의 `junees cron add/remove/rm/pause/resume/run/daemon`(표 `STATE_CHANGING`, 나중에 `plugin install` 같은 항목을 더함)을 알아보고, 명령 정책은 게이트가 없을 때(`-p`, task, 예약 실행, approval off) 막고 게이트가 있으면(`ToolSettings::approval_gate`) 승인 주의 신호(`change Junees's own state`)로 넘긴다. claude-code 백엔드는 같은 표로 `Bash(...)` 거절 규칙. cron 데이터 폴더의 거절 문구는 명령 이름을 빼고 "사용자만 바꾼다"로. `every`/`in`은 10년 이하이고 `next_after`는 넘침 검사 산술, ISO 시각은 `str::get`으로 잘라 ASCII 밖 글자가 형식 오류, 작업 찾기는 id, 이름, id 앞부분 순서
- 남은 위험: claude-code 백엔드의 토큰 한도는 사후 기록뿐이다. 실제 API, 실제 디스코드, 실제 systemd로는 확인하지 않았다

### 웹훅 수신 (로드맵 7단계 A)
- 새 모듈 `src/webhook/`(`http.rs`, `signature.rs`, `store.rs`, `template.rs`, `run.rs`, `server.rs`(+ `server/tests.rs`), `cli.rs`, `command.rs`, `mod.rs`). 공유 파일은 연결만: `lib.rs`, `cli.rs`(`Command::Webhook`, 도움말), `main.rs`(명령 연결, 처음 실행 마법사 제외, `/webhooks`), `slash.rs`, `gateway/bot.rs`(`!webhooks`), `config_file.rs`(`webhook_max_time`, `webhook_max_tokens`), `session.rs`(`WEBHOOK`), `tools/settings_file.rs`(데이터 폴더 `webhooks`), `tools/self_command.rs`(`webhook add/remove/rm/pause/resume/serve/test/run`)
- cron 재사용(`refactor(cron)` 커밋): `Engine::run`이 `Job` 대신 `Spec`(프롬프트, 폴더, 세션 source/channel, 시스템 문단)을 받고 `Job::spec`이 작업의 것을 만든다. `deliver::Report`는 작업 대신 source/label/전달처를, `store`는 `lock_file`/`read_private`/`write_private`를, `output`은 `write_text`를, `command`는 `engine_in`/`cancel_on_signals`를, `daemon`은 `wait_limited`/`signal_group`을, `limits_from`은 다른 설정 이름을 내놓는다. cron의 동작과 테스트는 그대로(제목 줄의 `junees cron`도 같다)
- HTTP: hyper 대신 직접 만든 수신기. 웹훅 송신자는 길이 있는 작은 POST만 보내므로 요청 줄, 헤더(16 KiB, 431), `Content-Length` 본문(1 MiB, 413), chunked/길이 없음 411, 길이 헤더 여러 개가 다르거나 숫자가 아니면 400, `Expect: 100-continue` 답, 응답 하나 뒤 연결 종료(keep-alive 없음), 요청 전체 10초(408)로 충분했다. hyper는 reqwest 때문에 이미 잠금 파일에 있지만 server 기능과 hyper-util 서버 쪽이 더 들어오고, 믿어야 할 코드가 더 많다
- 서명: `ring`(rustls가 이미 빌드하는 0.17)을 직접 의존성으로(`default-features = false`, 새로 빌드되는 크레이트 없음). `hmac::verify`가 상수 시간 비교. 테스트는 RFC 4231 1, 2, 3, 4, 6, 7번과 GitHub 문서의 예(`It's a Secret to Everybody` / `Hello, World!`). `sha256=` 접두, 64자 hex(대소문자), 앞뒤 공백 허용, 그 밖은 형식 오류
- 판단 순서: 메서드(405) -> 경로 이름(404) -> 길이(411/400/413) -> 경로 찾기(404) -> 시크릿 없는 경로의 요청 검사(루프백 리스너, 루프백 `Host`와 포트, 브라우저/프록시 헤더 없음은 403, JSON 아니면 415) -> 본문 읽기(`100 Continue`는 여기서) -> 종료 중(503) -> 서명(401) -> 이벤트 헤더(400)와 이벤트/전달 id 형식(`[A-Za-z0-9_.-]`, 400) -> JSON(400) -> GitHub ping(200) -> 멈춤(503) -> 필터(202 ignored) -> 중복(200) -> 대기 상한(429) -> 202 queued. 서명이 멈춤과 필터보다 먼저라 서명 없는 요청은 경로 상태를 알 수 없다. 중복 기억은 `<경로>/<id>`로 최근 1000개, 줄에 넣은 요청만 기억해서 429로 거절된 요청은 다시 받는다. 실행이 `ok`로 끝나지 않으면(`Runner::run`이 false) 그 id를 잊어 GitHub의 Redeliver(같은 `X-GitHub-Delivery`)로 다시 돌릴 수 있다
- 줄과 실행: 경로마다 `VecDeque`와 작업자 하나(`Runner` 트레이트, 실제는 `ProcessRunner`, 테스트는 세마포어로 붙잡는 가짜). 실행은 `current_exe() webhook run <이름> --run-id <r>`을 `/`에서 자기 프로세스 그룹으로, 요청 JSON은 표준 입력(쓰기는 별도 태스크, 프로세스가 끝나면 abort), 모든 경로의 시크릿 변수는 `env_remove`. 자식이 `last`를 running으로 적고 경로 폴더로 옮겨 cron 엔진(`session::WEBHOOK`, `WEBHOOK_NOTE`)으로 돌린 뒤 출력 파일, 전달, 기록. 끝난 뒤 `last.run_id`가 그 실행이 아니거나 running이면 서버가 실패(`the run ended without a result (...)`)로 기록하고 전달한다(cron 데몬과 같은 방식). 시간 한도 + 60초면 SIGINT, 30초 뒤 SIGKILL(`wait_limited`). `webhook test`와 `webhook run`은 설정 조회를 감싸 모든 경로의 시크릿 변수를 `hidden_env`에 더한다(사용자 셸에서 도는 `test`도 bash에 시크릿이 보이지 않게)
- 템플릿: `{{event}}`, `{{action}}`, `{{delivery}}`, `{{route}}`, `{{payload}}`, `{{payload.a.b}}`(숫자는 배열 번호). 모르는 이름과 닫히지 않은 `{{`는 추가할 때 거절. 값은 `escape_hidden`, 값마다 4000자(`{{payload}}` 20000자, 문자 단위로 자르고 남은 글자 수 표시), 요청마다 `random_hex(16)` 이름의 `<webhook-data-...>` 태그로 감싼다. 고정 태그면 값 안에 닫는 태그를 넣어 빠져나올 수 있어서 이름을 무작위로 했다. 맨 앞 문단은 경로 이름(추가할 때 검사)과 이벤트 이름(형식 검사, 백틱은 `'`)만 쓴다
- 종료: 첫 SIGINT/SIGTERM은 리스너를 닫고 대기 요청을 버린 뒤(개수 로그) 도는 실행 수(`watch` 채널)가 0이 될 때까지, 두 번째 신호는 `Runner::interrupt`(실행 그룹에 SIGINT)
- 테스트: 단위(`src/webhook/*`: HTTP 경계 17가지와 정확히 1 MiB, 100-continue, 느린 클라이언트, 응답 형식, HMAC 벡터와 틀린/없는/형식 오류 서명, 경로 판단 전체, 루프백 규칙, 중복과 1000개 기억, 경로마다 하나씩과 20개 뒤 429와 순서, 종료 시 대기 버림과 실행 기다림, 두 번째 신호, 408, 서버 잠금, 템플릿 치환/정리/상한/검사, 저장 권한/형식/시크릿 파일 권한, 필터와 이름, 인자 파싱, 추가 검사 12가지, 시크릿 숨김, Scripted provider로 웹훅 세션과 출력 파일과 디스코드 전달), 통합 `tests/webhook.rs`(바이너리 add/list/test/pause/resume/rm, `serve --listen 127.0.0.1:18150`에 reqwest로 서명한 요청, 자식 실행의 bash에 시크릿 없음, SIGTERM). 시크릿 변수 제거, 서명 확인, 중복, 대기 상한, 루프백 규칙, 필터, 값 이스케이프, 종료 때 기다림, chunked 거절, 데이터 폴더 등록, 결과 없이 끝난 실행 기록을 하나씩 되돌리는 변이 스크립트로 각 테스트가 실패하는 것을 확인했다
- 리뷰 반영(Momus, PR #41): 시크릿 없는 경로를 브라우저의 다른 사이트 요청(`text/plain` POST는 preflight 없음)과 DNS rebinding이 부를 수 있었다. 루프백 리스너는 듣는 주소일 뿐 보낸 쪽이 아니어서, 헤더 단계에서 `Host`(루프백 리터럴 + 포트, 하나만), `Origin`/`Sec-Fetch-*`, 프록시 헤더(`X-Forwarded-For`, `Forwarded`, `CF-Connecting-IP`, `X-Real-IP`), `Content-Type: application/json`을 본다(리뷰의 probe 요청을 그대로 테스트로). systemd 예시에 `KillMode=mixed`와 `TimeoutStopSec`(기본 `control-group`은 자식 실행에도 SIGTERM을 보낸다, `systemd-run --user`로 확인). 시크릿 파일은 `$JUNEES_HOME/secrets/`에만 두게 하고, 그 폴더를 설정 파일과 같은 읽기/쓰기 보호에 넣었다(경로 목록을 들고 다니는 대신 고정 폴더: 경로를 추가하기 전에 시작한 세션과 systemd 환경 파일도 막힌다. `webhooks/`는 읽기를 허용하는 데이터 폴더라 쓰지 않았다). 실패한 실행의 전달 id는 잊는다. 동시 연결 64개(넘으면 503 후 닫음), 경로와 길이를 본문 전에 확인, 헤더 끝은 이어 찾기
- 남은 위험: 터널/리버스 프록시 뒤에서는 모든 연결이 루프백이다. 시크릿 없는 경로는 프록시 헤더나 다른 `Host`가 붙은 요청을 거절하지만, 표시 없이 `Host`를 바꿔 넘기는 프록시라면 받는다(README에 적음). 서명이 맞아도 PR 본문과 코멘트는 누구나 쓰는 글이라 데이터 태그만으로 프롬프트 주입을 막을 수는 없다. 경로가 많으면 동시에 그만큼 실행된다(전체 상한 없음). 중복 기억은 메모리에만 있어 서버를 다시 띄우면 GitHub의 재전송이 다시 돈다. `secrets/` 보호는 설정 파일과 같은 차단 목록이라 위 폴더에서 읽는 명령(`grep -r x ~`)이나 실행 중에 만든 경로는 막지 못한다. 느린 연결 64개면 10초 동안 다른 요청이 503을 받는다. 실제 GitHub, API, 디스코드로는 확인하지 않았다
- 미룬 것: GitHub 흐름 프리셋(`webhook add-github`, 7단계 C), TLS, keep-alive, 실패 재시도, 경로마다 다른 한도, 대화/게이트웨이에서 경로 추가

### GitHub 도구 (로드맵 7단계 B)
- 새 모듈 `src/github/`(`mod.rs`, `client.rs`, `tool.rs`, `format.rs`, `tests.rs`). 공유 파일은 연결만: `lib.rs`, `config.rs`(`Config::github`), `config_file.rs`(`github_token`, `github_api_url`, `github_repos`, `github_allow_unattended`), `tools/mod.rs`(`SECRET_ENV_VARS`에 `JUNEES_GITHUB_TOKEN`), `approval.rs`(`github` 질문 갈래, `ASKED_EVERY_TIME`), `main.rs`/`gateway/engine.rs`/`cron/run.rs`(등록, `/github`), `slash.rs`, `cli.rs`(도움말). 새 의존성 없음(reqwest, serde_json 그대로)
- 도구 하나(`github`, `action` 필드)로 했다. 도구 목록이 11개 늘지 않고(요청마다 보내는 도구 정의와 캐시 앞부분이 작다), 승인 질문과 무인 허용 목록이 액션과 리뷰 event로 판단하기 때문이다. 액션별 입력 검사는 도구 안에서 하고 오류는 `ToolOutput::error`
- 승인: `Approval::request`에 `github` 갈래 하나를 더하고 질문 내용(대상, 이유, 종류, 미리보기)은 `github::question`이 만든다. 쓰기마다 종류가 있어 `risky`에서도 묻고, 읽기는 종류가 없어 `all`만 묻는다. merge의 종류는 `(asked every time)`으로 끝나고, "항상" 답은 이 꼬리의 종류를 허용 목록에 넣지 않는다(`Request`에 필드를 더하지 않아 다른 모듈의 `Request` 리터럴이 그대로)
- 무인 판단: 도구가 등록될 때 승인 게이트가 있는지(`asks`) 받는다(대화는 `gate.is_some()`, 게이트웨이는 `asks()`, 예약 작업은 `false`). 게이트가 없으면 `JUNEES_GITHUB_ALLOW_UNATTENDED`의 쓰기만 실행한다. 그래서 대화에서 `JUNEES_APPROVAL=off`도 무인으로 친다(묻는 사람이 없으므로 merge가 질문 없이 돌지 않게). 허용 목록 이름은 액션이 아니라 쓰기 종류(`comment`는 `pr_comment`와 `review_reply`, `review`와 따로 `approve`, `pr_create`, `merge`)
- repo 범위: `github_repos`가 비면 시작할 때 읽은 작업 폴더 origin 하나. 읽기에도 적용한다. origin은 `git -c core.fsmonitor=false remote get-url origin`을 task 모드와 같은 환경 정리(저장소 변수, 비밀 변수 제거)로 한 번 실행해서 읽는다. 다음 실행은 origin을 다시 읽고 모델은 `.git/config`를 묻지 않고 고칠 수 있으므로, `github_repos`가 비어 있으면 묻지 않는 쓰기는 허용 목록에 있어도 거절한다(PR #42 리뷰)
- bash의 `gh`: 서버의 `gh` 로그인으로 도구의 승인과 허용 목록을 건너뛰지 않게, 명령 정책이 `gh` 쓰기(`src/tools/gh_command.rs`의 표, 쓰기 메서드나 본문이 있는 `gh api`)를 `self_command`처럼 다룬다: 게이트가 없으면 거절, 있으면 `risky`에서도 묻는 주의 신호(merge는 `(asked every time)` 종류). 차단 목록이라 `gh` 별칭, 스크립트, `curl`로 API 직접 호출은 못 막는다(PR #42 리뷰)
- 신뢰 경계: 결과 첫 줄 안내 + 남이 쓴 긴 글은 `    | ` 인용 줄 + `prompt_text::escape_hidden`(한 줄 값은 줄바꿈도 `\n`으로). diff는 줄마다 `+`/`-`/공백/`@@`로 시작하므로 인용 없이 이스케이프만 한다(파일 머리 `=== ` 줄을 흉내 낼 수 없다). 보낼 글은 `prompt_text::check_plain`과 `secrets::find_outgoing_secret`(메모리/스킬의 `find_secret`과 같되, 커밋 링크와 SHA를 담는 리뷰를 위해 정확히 40/64자인 16진수는 통과. PR #42 리뷰), 그리고 설정한 토큰 값 자체는 입력 어디에 있든 거절

### 세션 검색 (로드맵 8단계 B)
- 새 모듈 `src/search/`(질의 매칭 `query.rs`, 줄 단위 읽기 `scan.rs`, 출력 `format.rs`, 도구 `tool.rs`, 사람용 옵션 `args.rs`). 공유 파일은 연결만: `lib.rs`, `main.rs`(대화 도구 등록, `/search`, `junees sessions search`), `cli.rs`(명령, 도움말), `slash.rs`, `gateway/engine.rs`, `cron/run.rs`, `task/runner.rs`. 새 의존성 없음
- 찾는 글: 사용자 입력, 모델 텍스트, 압축 요약(`compact`), `append_text`, Claude Code 턴의 입력과 답, 도구 결과. 도구 결과는 같은 파일 안의 `tool_use` id로 도구 이름을 붙이고, 비워진 결과(`CLEARED`, `INTERRUPTED`)와 `session_search` 자신의 결과는 뺀다(다음 검색이 이전 결과를 다시 찾지 않게)
- 결정: AND는 세션 전체가 아니라 한 메시지 안에서다. 세션 전체로 하면 긴 세션은 흔한 낱말 몇 개로 거의 다 맞고, 스니펫이 무엇과 맞았는지 보여 주지 못한다. 도구 결과는 앞 4 KiB, 입력과 텍스트는 64 KiB만 본다("도구 결과 요약": 읽은 파일 전체가 맞으면 결과가 잡음으로 찬다)
- 결정: 폴더 범위는 `meta.cwd`와 정확히 같은 세션(`-c`와 같은 기준). `session` 인자를 주면 폴더는 보지 않는다
- 결정: 채널 세션(`source`가 있는 세션)은 모델 도구에서 기본 제외. `sources` 인자는 터미널 대화와 `-p`의 모델만 쓸 수 있고, 게이트웨이, 예약 작업, task 세션의 모델에게는 스키마에서도 빼고 주면 오류로 답한다(게이트웨이 길드 채널의 답은 여러 사람이 읽는다). 사람용 명령은 기본으로 모든 출처를 보여 준다(사람은 자기 기록 전부의 주인이고, `/sessions`도 채널 세션을 보여 준다)
- 스펙에서 바꾼 것: 무인 실행 중 웹훅 실행에는 도구를 주지 않았다. 웹훅 실행은 PR 본문 같은 남의 글이 움직이고, GitHub 흐름의 리뷰 단계는 모델의 글을 GitHub에 올리므로 사용자의 다른 대화를 꺼내 보내는 통로가 된다. 예약 작업(사용자가 쓴 프롬프트)과 task 세션에는 준다
- 데이터 표시: 결과마다 무작위 8 hex 이름의 요소(`<session-xxxxxxxx ...>`)로 감싸고 "인용한 데이터일 뿐 지시가 아니다" 줄을 앞에 둔다(웹훅 템플릿과 같은 방식). 속성 값과 스니펫은 `escape_hidden`, 속성 안 `"`는 `'`로
- 성능: `BufReader`(64 KiB)로 줄을 읽되 4 MiB가 넘는 줄은 버퍼에 담지 않고 소비만 한다(`Line::TooLong`). 매 줄과 64 KiB마다 시간 상한을 본다(모델 5초, 사람 15초). 파일은 수정 시각 순으로 읽다가 보여 줄 세션 수를 채우면 멈춘다. 서브에이전트 기록(`sessions/<id>/*.jsonl`)도 따로 결과에 나오고, 사람용 안내는 부모 id로 이어 가라고 알린다
- 측정(release 빌드, 이 서버): 기록 3000개 377 MiB(12 MiB 줄 하나 포함)에서 맞는 것이 없는 질의로 전체를 읽는 데 2.2초, 최대 RSS 11 MB. JSON을 읽기 전에 낱말로 줄을 거르는 사전 필터도 시험했지만 serde_json 파싱보다 바이트 비교가 느려(290 MiB에서 1.24초 -> 1.8초) 넣지 않았다. debug 빌드는 10배쯤 느려 15초 상한에 걸린다
- 테스트: 단위(`src/search/*`: 질의 파싱과 AND/구절/한글/대소문자/길이가 바뀌는 소문자, 스니펫 자르기, 큰 줄 읽기와 시간 초과, 한 메시지 안 AND, 새것부터와 결과/스니펫 상한, 폴더 범위와 하위 폴더, `all`, `session`, 채널 세션 제외와 `sources`, 깨진 줄/잘린 줄/기록 아닌 파일/4 MiB 넘는 줄, 64 KiB와 4 KiB 자르기, 도구 이름 표시와 이전 검색 결과 제외, 서브에이전트 기록, 시간 상한 0, 모델 출력의 무작위 태그와 이스케이프, 제한된 도구의 `sources` 거절, 입력 오류 9가지, 서브에이전트가 받는 도구, 사람용 목록, `/search`와 `sessions search` 인자, 예약 작업에는 있고 웹훅 실행에는 없는 도구), 통합 `tests/session_search.rs`(바이너리 `-p`에서 가짜 API의 `session_search` 호출 결과, 대화의 `/search`, `junees sessions search`)
- 미룬 것: 색인 파일, 시간 범위와 정규식 검색, 하위 폴더 포함 옵션, `/search` 결과 번호로 바로 이어 가기(지금은 `--resume` 안내), claude-code 백엔드 모델의 검색(MCP로 줄 수 있음), 게이트웨이 `!search`
- 남은 위험: 지금 대화의 기록도 결과에 나온다(모델이 이미 보는 내용). 결과에는 지난 대화의 도구 출력 앞부분이 그대로 들어가므로, 같은 폴더의 세션이 담은 비밀이 지금 대화의 모델에게 다시 보일 수 있다(그 세션 때도 모델이 본 내용). 시간 상한에 닿으면 오래된 세션은 찾지 못한다

### 사용량과 비용 (로드맵 8단계 2차 A)
- 새 모듈 `src/usage/`(가격 `prices.rs`, 기록 읽기 `scan.rs`, 출력 `report.rs`, 옵션 `args.rs`). 공유 파일은 연결만: `lib.rs`, `main.rs`(`/usage`, `junees usage`), `cli.rs`(명령, 도움말), `config_file.rs`(`prices` 키), `search/`(줄 읽기와 출처 판단을 `pub(crate)`로). 새 의존성 없음

- 결정: 서브에이전트 기록(`sessions/<id>/*.jsonl`)은 읽지 않고 부모의 `subagent_usage`로 센다(둘 다 세면 두 번 센다). 대신 그 항목은 여러 호출의 합이라 Haiku 5.5의 긴 프롬프트 가격은 적용하지 않는다(기본 가격)

- 결정: 사용량이 아닌 줄은 Junees가 쓴 줄의 앞부분(`{"type":"<종류>"`)으로 알아보고 파싱하지 않는다. 세션 검색의 측정과 달리 여기서는 큰 메시지 줄을 통째로 `Entry`로 만들 필요가 없어서다. 다르게 쓰인 줄(손으로 쓴 JSON)은 전체를 파싱한다
- 스펙에서 바꾼 것: 가격 덮어쓰기는 모델마다 `price_<model>` 키가 아니라 한 키 `prices`(`JUNEES_PRICES`)에 `<모델>=<입력>/<출력>[/<캐시 쓰기>/<캐시 읽기>]` 목록으로 했다. 설정 파일은 키마다 환경 변수 하나가 대응하는 고정 목록(`KEYS`)이라 모델 이름이 들어간 키는 그 구조(모르는 키 오류, 파일만으로는 Junees가 읽지 않는 변수를 못 만든다는 보장)를 바꿔야 해서다

### MCP Streamable HTTP (로드맵 9단계 A)
- 명세: 2026-07-28 Streamable HTTP 바인딩(`basic/transports/streamable-http.md`)과 Versioning, 이전 판 2025-11-25 `basic/transports.md`를 `curl`로 markdown을 받아 따랐다(2026-11-11). 6단계 A의 stdio `Connection` 자리에 `Link`(`src/mcp/link.rs`: `Stdio(Connection)` / `Http(HttpConnection)`)를 두어 승인, trust, 도구 이름, 결과 변환, `/new` 재시작은 stdio와 같은 코드를 탄다
- 새 모듈 `src/mcp/http/`(`mod.rs` 연결, `target.rs` url/headers, `meta.rs` 요청 메타데이터 헤더, `sse.rs`, `tests.rs`). 공유 파일은 연결만: `mcp/config.rs`(`command` 또는 `url`), `mcp/server.rs`(`Link`, HTTP 연결 분기, handshake 보조 함수 `pub(super)`), `mcp/conn.rs`(`CallError::Failed`), `mcp/mod.rs`(`start_servers_with_env`, `/mcp` 전송 표시), `config.rs`(헤더 변수를 `hidden_env`에), `doctor/`. 새 의존성 없음(reqwest 그대로, `chunk()`로 읽고, Base64는 직접)
- 설정: `servers.<이름>.{url, headers, enabled, trust, timeout_secs}`. `url`은 https, http는 루프백(`localhost`, 127/8, `::1`)만, userinfo 거절, fragment 버림. `headers` 값은 `env:NAME` 또는 `<단어> env:NAME`(`Bearer env:TOKEN`)만: 파일에 비밀이 없고, 오류는 값을 인용하지 않는다. 전송이 쓰는 헤더(`Accept`, `Content-Type`, `Host`, `Mcp-Session-Id`, `MCP-Protocol-Version`, `Mcp-Method`, `Mcp-Name`, `Mcp-Param-*`, `Last-Event-ID` 등)는 설정 불가. 값은 시작할 때 읽어 `HeaderValue::set_sensitive`. 참조된 변수는 `Config::read`가 `hidden_env`에 더한다(bash에서 `echo $TOKEN`으로 못 읽게)
- 결정(스펙의 `env:NAME`에 더함): 대부분의 서버가 `Authorization: Bearer <토큰>`을 받으므로 앞에 단어 하나를 허용했다. 템플릿(`${A}-${B}`)은 문자열 일부에 비밀을 끼워 넣을 수 있어 받지 않는다
- 세대 판별(Streamable HTTP Backward Compatibility): 2026-07-28 헤더를 붙인 `server/discover` POST. 결과면 modern, -32022면 지원 버전을 알리며 실패, -32020/-32021(modern 오류)도 실패(대체 금지), 4xx나 modern이 아닌 JSON-RPC 오류면 legacy `initialize`(2025-11-25 요청) -> `notifications/initialized`(202). 5xx와 연결 실패는 실패. stdio와 달리 탐색 시간 제한(5초)으로 legacy로 가지 않는다: HTTP는 항상 응답이 오고 시작 전체 30초가 덮는다. `initialize`도 4xx면 2024-11-05 HTTP+SSE 전송은 지원하지 않는다고 적는다
- modern 요청: `MCP-Protocol-Version: 2026-07-28`, `Mcp-Method`, `tools/call`/`resources/read`/`prompts/get`에 `Mcp-Name`, `_meta`. `x-mcp-header`: 클라이언트 MUST라서 구현했다. `tools/list`에서 규칙(빈 이름, tchar 밖, 대소문자 무시 중복, string/integer/boolean 외, `properties` 체인 밖의 표시 — `items`, `anyOf`, `$defs` 등. `const`/`default`/`enum`/`examples` 값은 데이터라 보지 않음)을 어긴 도구는 빼고 시작 줄에 이유. 호출 때 그 경로의 값을 `Mcp-Param-<이름>`으로(정수는 ±2^53-1 안만, null/없음/다른 타입은 생략), 평범한 ASCII가 아니거나 앞뒤 공백, 표시 패턴과 같은 값은 `=?base64?...?=`. legacy 서버에는 붙이지 않는다
- legacy 세션: `initialize` 응답의 `Mcp-Session-Id`(보이는 ASCII 0x21~0x7E가 아니면 실패)를 이후 모든 요청에, 정해진 버전을 `MCP-Protocol-Version`에. 세션을 붙인 요청이 404면 새 세션(`initialize`부터, 동시에 404를 받은 요청들은 세대 번호로 한 번만 다시 열기) 후 한 번 다시 보냄. 종료 때 `DELETE`(10초, 결과 무시). 응답 스트림의 서버 요청은 `ping`에 빈 결과, 나머지는 -32601을 POST로(백그라운드)
- 응답: `application/json`(배치 배열이면 id로 찾음) 또는 `text/event-stream`(우선 이벤트 `id: x / data:`, 주석, 진행 알림을 건너뛰고 그 요청 id의 응답까지). 2xx인데 본문 형식이 없거나(202) 다른 content type이면 실패. 오류 상태는 본문 64 KiB까지 읽어 JSON-RPC 오류면 그 오류로. 응답 전체 64 MiB(`conn::MAX_MESSAGE_BYTES`) 넘으면 그 호출만 실패. 리다이렉트는 `Policy::none()` + 3xx를 실패로(`url`에 최종 주소 안내). 루프백이면 프록시를 쓰지 않음, 연결 10초
- 취소: `timeout_secs` 또는 턴 취소로 future가 drop되면 연결이 닫힌다(modern은 그것이 취소). legacy는 끊김이 취소가 아니므로 drop guard가 `notifications/cancelled`(requestId, 같은 세션)를 따로 POST. `initialize`는 취소하지 않는다
- 오류 문구: reqwest 오류는 최상위(URL 포함)를 버리고 원인만(`cannot connect: client error (Connect): tcp connect error: Connection refused`). URL, 헤더 값, 세션 id는 어디에도 출력하지 않는다. `/mcp`와 doctor는 URL의 origin(`scheme://host:port`)과 헤더 이름, 변수 이름만
- doctor: `url` 서버는 형식(설정 읽기 그대로)과 헤더 변수 존재만 보고 연결하지 않는다. 변수가 없으면 실패와 고칠 방법
- 범위 밖(1차): OAuth 인가 흐름, legacy GET 알림 스트림과 `Last-Event-ID` 이어 받기(답 없이 끊긴 스트림은 그 호출 실패), `subscriptions/listen`, 2024-11-05 HTTP+SSE 전송, MRTR(`input_required`는 stdio처럼 미지원 오류), `HeaderMismatch` 뒤 `tools/list` 재조회와 재시도, HTTP/2(reqwest 기본 기능 꺼짐), 서버 응답이 정한 legacy 버전이 바뀐 재세션 뒤의 도구 목록 갱신
- 테스트: 단위 `src/mcp/http/tests.rs`(테스트 안 루프백 가짜 HTTP MCP 서버: 두 세대 x JSON/SSE, modern 헤더와 `_meta` 검사·불일치면 -32020, legacy 세션과 404, 우선 이벤트/주석/진행 알림/조각난 CRLF 응답, 서버 ping/roots 요청). 두 세대 핸드셰이크와 헤더, x-mcp-header 값(한글 Base64)과 규칙 위반 도구 제외, legacy 세션 id/버전 헤더/DELETE/종료 뒤 호출 실패, 404 뒤 새 세션과 재전송(modern 404는 그냥 실패), -32022면 `initialize` 안 보냄, 시간 초과와 취소(modern은 서버가 연결 닫힘을 봄·cancelled 없음, legacy는 cancelled의 requestId와 세션), 크기 상한(JSON/SSE), 307 거절과 대상 서버에 요청 없음, 연결 실패/500/405 문구와 URL·토큰·경로 비노출, 변수 없음이면 요청 0, `/mcp` 문구와 trust. `target.rs`(url 규칙, 헤더 값 규칙과 비노출, 민감 표시), `meta.rs`(명세 표의 인코딩 예 전부, x-mcp-header 규칙), `sse.rs`(모든 분할 지점에서 같은 이벤트), `mcp/config.rs`, `config.rs`(헤더 변수 숨김), `doctor`. 통합 `tests/mcp_http.rs`(바이너리 `-p`: 모델의 도구 호출이 SSE 응답으로 돌아오고 Authorization이 변수 값, bash는 그 변수를 못 봄(`[unset]`); 변수가 없으면 그 서버만 빠지고 요청 0)
- 변이 검사(origin 없는 별도 clone, 테스트 하나씩): 헤더 변수 숨김(단위와 바이너리 각각), 리다이렉트 금지, 404 재세션, legacy 취소 알림, SSE 크기 상한, 세션 id 헤더, 오류 문구의 URL, `Mcp-Param` 헤더, -32022 대체 금지, 4xx만 legacy 대체, 규칙 위반 도구 제외, http 루프백 제한, doctor 변수 점검을 하나씩 되돌린 14개 모두 해당 테스트가 실패했다
- 상호 운용 스모크(커밋하지 않음): 공식 Python SDK `mcp` 2.3.0 `MCPServer`의 Streamable HTTP를 루프백에 띄우고 바이너리 `-p`(가짜 API)로 `add` 도구를 불렀다. JSON/SSE x modern/legacy 네 가지 모두 `sum=42`. legacy는 SDK 앞에 `server/discover`만 평문 400으로 막는 ASGI 래퍼를 두어 SDK의 legacy 경로(세션 id, 2025-11-25 협상, 종료 DELETE)를 탔다
- 남은 위험: 헤더 변수는 Junees 프로세스 환경에 있어야 하고(`PR_SET_DUMPABLE`로 `/proc/<junees>/environ`은 막혀 있음) 자식에게서만 숨긴다. 같은 변수를 bash의 다른 도구가 써야 하면 이름을 나눠야 한다. 원격 서버가 돌려준 내용은 stdio와 같이 데이터로 표시할 뿐 신뢰하지 않는다. legacy 서버가 응답 스트림을 답 없이 끊는 경우(재연결 기대) 그 호출은 실패로 끝난다

### MCP OAuth 인가 (로드맵 9단계 2차 A)

- 목표: 9단계 A의 `url` 서버에 MCP 인가 명세(2026-07-28 `basic/authorization`, 2025-11-25와 같은 흐름에 RFC 9207 `iss` 확인이 더해짐)를 붙인다. 코드는 `src/mcp/oauth/`.
- 흐름: 토큰 없는 `server/discover`에 401 + `WWW-Authenticate: Bearer resource_metadata=...` -> 보호 자원 메타데이터(RFC 9728, 없으면 well-known 경로 삽입 -> 루트) -> `resource`가 서버 주소를 덮는지 확인 -> 인가 서버 메타데이터(RFC 8414/OIDC 순서, `issuer` 글자 그대로 일치, `S256` 없으면 중단) -> 클라이언트(`oauth.client_id` 또는 동적 등록 RFC 7591, `application_type: native`) -> PKCE S256 + `state` + `resource` + scope로 인가 주소 출력 -> 127.0.0.1 임의 포트 한 번 수신기 또는 붙여 넣은 주소 -> `iss` 확인 -> 코드 교환(`resource` 포함) -> `$JUNEES_HOME/secrets/mcp-oauth/<서버>.json`(0600, 폴더 0700).
- 로그인은 `junees mcp login <서버>`와 대화 `/mcp login <서버>`만 시작한다(모델의 bash는 상태 변경 명령으로 막거나 묻는다). 시작 시 401이면 그 서버만 실패하고 안내한다. 무인 실행(cron, webhook, `-p`, 게이트웨이)은 저장된 로그인만 쓰고 갱신만 한다.
- 사용: 모든 요청에 `Authorization: Bearer`(민감 표시), 저장된 `url`과 지금 `url`이 다르면 보내지 않음. 만료 1분 전과 401 뒤 한 번 갱신(동시 401도 한 번, 다른 프로세스와는 폴더 flock, 회전된 리프레시 토큰은 디스크에서 다시 읽음). 403 `insufficient_scope`는 실패시키고 scope를 기억해 다음 로그인이 함께 요청(step-up).
- 리뷰 반영(PR #56): 갱신은 폴더 잠금 안에서 저장된 파일을 보고, 파일이 없거나(로그아웃) `server_url`/`resource`가 다르면(다른 주소의 새 로그인) 갱신도 쓰기도 하지 않고 실패한다. 로그인의 저장과 로그아웃도 같은 잠금을 잡고, 잠금 대기는 토큰 요청 한도 + 15초. 루프백 http 엔드포인트는 MCP `url`이 루프백일 때만. `oauth.scope`가 있으면 403 안내가 그 값에 scope를 더하라고 말한다. 등록 답의 `none`은 secret이 있어도 공개 클라이언트.
- 결정: mcp.json `headers`의 `Authorization`이 이긴다(로그인 거절, 저장된 로그인 무시, `oauth`와 같이 쓰면 설정 오류). 다른 헤더는 토큰과 함께 보낸다. Client ID Metadata Document는 호스팅할 고정 https 주소가 없어 직접 하지 않고, 사용자가 호스팅한 URL을 `oauth.client_id`로 줄 수 있게만 했다. 브라우저는 열지 않고 주소만 출력한다.
- doctor: 오프라인은 저장된 로그인(있는지, 이 주소의 것인지, 권한, 발급자, 만료와 갱신 가능 여부, 값은 `[hidden]`), `--online`은 인가 서버 찾기만(등록/토큰 요청 없음).
- 검증: `src/mcp/oauth/tests.rs`의 루프백 가짜 인가 서버+MCP 서버(메타데이터, 등록, authorize 흉내, token의 PKCE/redirect_uri/resource 확인, refresh, 401/403 챌린지), `tests/mcp_oauth.rs` 바이너리 `mcp login` 붙여 넣기와 `-p`, `mcp logout`.
- 범위 밖: Client ID Metadata Document 호스팅, 토큰 철회(RFC 7009), `private_key_jwt`/DPoP, 게이트웨이 채널의 로그인, legacy GET 스트림.

### 이미지 입력 (로드맵 9단계 1차 B)

### bash 실행 격리 (로드맵 10단계 B)
- 문서: kernel.org Landlock 사용자 API 문서(https://docs.kernel.org/userspace-api/landlock.html, 2026-11-12 `curl`). 이 서버 커널 6.8은 ABI 4(파일과 TCP).
- 새 모듈 `src/sandbox/`(`mod.rs` 설정과 판단, `landlock.rs` 시스템 호출과 규칙, `tests.rs`). 공유 파일은 연결만: `lib.rs`, `ToolSettings.sandbox`, `Config`의 설정 읽기와 `config_file::KEYS`, `Bash::with_settings`/`run`, `cron::run::Trigger::tool_settings`(무인 실행), `SettingsFile`의 보호 경로와 데이터 폴더 목록, doctor 연결.
- 결정: `landlock` 크레이트 대신 libc `syscall`로 직접(호출 셋, 구조체 둘). 규칙은 부모에서 만들고(O_PATH 열기, 폴더 읽기) 자식은 `pre_exec`에서 `prctl(PR_SET_NO_NEW_PRIVS)`와 `landlock_restrict_self`만 한다(fork 뒤에 안전한 시스템 호출 둘). 규칙 fd는 close-on-exec라 bash에 남지 않는다.
- 결정: Landlock 규칙은 허용만 하고 아래로 상속되므로, 보호 경로(설정 파일, `mcp.json`, `secrets/`, 웹훅 실행의 git/gh 자격 증명)를 품은 폴더는 자기 대신 안의 항목마다 규칙을 받는다(`grant_except`, 심볼릭 링크 항목은 건너뛴다). 읽기 권리는 `EXECUTE | READ_FILE`, 폴더 목록(`READ_DIR`)은 다루지 않는다(빼고 나열할 방법이 없다). 데이터 폴더는 쓰기에서만 뺀다. 쓰기는 작업 폴더, 임시 폴더, `sandbox_write`, 그리고 `/dev`의 기존 파일 쓰기만. ABI 2의 `REFER`로 비밀 파일을 읽을 수 있는 폴더로 옮기거나 링크하는 것도 커널이 막는다(테스트로 확인).
- 결정: `sandbox = auto|require|off`. 지정하지 않으면 대화, `-p`, 작업 모드는 `auto`, 예약 작업과 웹훅 실행은 `require`. `auto`는 지원하지 않는 커널에서(또는 `sandbox_network = 0`인데 ABI < 4) 첫 결과에 한 줄로 알리고 실행, `require`는 거절. 지원하는 커널에서 규칙을 만들지 못하면 모드와 상관없이 거절. 거부 목록 정책은 그대로 먼저 돈다.
- 결정: 플러그인 명령과 stdio MCP 서버는 묶지 않는다(사용자가 설치하고 켠 프로그램, 자기 상태와 네트워크 필요). claude-code 백엔드는 대상 아님. 네트워크 기본은 허용(`cargo`, `git fetch`가 깨지지 않게), 막을 때는 TCP connect/bind 전체.
- 스펙에서 더한 것: `sandbox_write`/`sandbox_read`의 `~/` 펼치기, bash 도구 설명에 `Permission denied`의 뜻 한 줄, 웹훅 실행의 자격 증명 읽기 금지, doctor의 두 번째 시험(설정 파일 열기가 실패해야 ok).
- 테스트: 단위(`src/sandbox/tests.rs`: 실제 커널로 작업 폴더 안 쓰기 성공과 밖 쓰기/덧붙이기/mkdir/옮기기 실패, 설정한 쓰기 폴더, 설정 파일·`mcp.json`·secrets 읽기 실패(`/proc/self/root` 경유와 하드 링크 포함), 홈이 작업 폴더일 때도 보호 유지, 웹훅 실행의 gh 자격 증명, 읽기 좁히기, `NoNewPrivs: 1`, 루프백 리스너 connect 실패/성공, 가짜 ABI 3과 가짜 미지원의 auto/require, 설정 읽기), doctor(실제 커널 시험, 가짜 미지원의 경고/실패/off, ABI 3 네트워크 경고, 잘못된 값), 바이너리(`tests/sandbox.rs`). 실제 커널 테스트는 Landlock이 없으면 이유를 찍고 건너뛴다. 확인: bash에서 규칙 적용을 빼면 실제 커널 테스트 8개가 모두 실패, 바이너리 테스트는 `JUNEES_SANDBOX=off`로 실패.
- 남은 위험: bind mount와 기존 하드 링크는 경로 기준인 Landlock이 막지 못한다. 보호 경로를 품은 폴더 바로 아래에는 새 파일을 만들 수 없고 실행 중 새로 생긴 항목은 읽지 못한다. 기본 설정에서는 작업 폴더 밖 캐시(`~/.cargo`, `~/.cache`)에 쓰는 명령이 실패하므로 `sandbox_write`가 필요할 수 있다. CI 러너 커널의 Landlock 지원은 확인하지 않았다(없으면 건너뛴다).
- 리뷰 반영(PR #62, 권장 2, 참고 4): (1) 보호 경로를 링크를 푼 경로와 쓰인 경로 둘 다로 계산하고, 보호 경로로 가는 길의 링크는 따라가지도 규칙을 주지도 않는다. `~/.junees`가 링크이고 홈에서 실행해도 링크를 옮기거나 바꿔 치지 못한다. (2) GitHub 흐름의 `--test-cmd`도 웹훅 실행의 bash와 같은 Sandbox(`flow::address::test_sandbox`, 기본 `require`)로 묶고, 묶을 수 없으면 실행하지 않고 단계가 실패한다. (3) 규칙을 만들며 나열하지 못한 폴더는 실행 전체를 거절하는 대신 길 위의 항목만 따라가고 나머지 항목에는 규칙을 주지 않는다(auto에서 격리를 끄는 길은 택하지 않았다: 묶인 명령이 `chmod`로 길 위의 폴더를 막아 다음 명령의 격리를 끌 수 있다). (4) 텔레그램 그룹에서 질문 대기 중의 `/단어 ...`는 답이 아니다. 웹 주소 경로 안의 `@이름`은 그대로 둔다(백틱 안은 평문이라 그대로 깨뜨린다). (5) doctor 테스트의 만료 시각을 시간 경계에서 30분 떨어뜨렸다(CI flaky).
- main(브라우저 도구, #61)과 합친 뒤 맞춘 것: (1) `docs/safety.md`의 묶지 않는 것에 브라우저를 더했다(`sandbox_network = 0`과 무인 실행의 `require`는 bash만 묶어, `browser_unattended`면 브라우저가 따로 네트워크로 나간다). (2) 브라우저 프로필을 임시 폴더(격리된 bash가 쓸 수 있다)에서 `$JUNEES_HOME/browser/<무작위>`로 옮기고, 그 폴더를 설정 파일처럼 숨기는 보호 경로(`SettingsFile::protected_paths`)에 더했다. 임시 폴더 아래 항목 하나를 거부 규칙으로 빼는 방법은 택하지 않았다: Landlock은 허용만 하므로 `/tmp`가 항목별 규칙으로 바뀌어 격리된 명령이 `/tmp`에 새 파일을 만들 수 없게 된다. 소켓 경로 상한(107바이트)은 Chrome의 TMPDIR에만 걸리므로, 프로필 안에서 넘으면 프로필은 상태 폴더에 두고 TMPDIR만 임시 폴더의 별도 폴더로 준다. 테스트: `sandbox/tests.rs`(실제 커널, 프로필의 쿠키 읽기, 덧붙이기, 새 파일, 새 폴더, 옮기기, 복사가 모두 실패), `browser/tests.rs`(설정 읽기, 짧은/긴 상태 폴더의 프로필과 TMPDIR, 실제 Chromium으로 소켓 폴더가 프로필 안에 생기고 닫은 뒤 비는지), `tests/browser.rs`(긴 `JUNEES_HOME`에서 바이너리 실행 뒤 프로필과 임시 폴더가 남지 않음).

### 텔레그램 후속 #58 (로드맵 10단계 C)
- 한 단어 경로(`/tmp is full`): 모르는 `/단어` 뒤에 글이 이어지면 보통 메시지로 넘긴다. 단, 봇 이름을 붙인 것(`/tmp@봇 ...`)과 Junees 터미널 명령(`slash::is_command`: `/model opus` 등)은 지금처럼 모르는 명령으로 답해 게이트웨이에 그런 명령이 없다고 알린다. 단어 하나뿐인 `/tmp`도 모르는 명령.
- 나뉘어 온 앨범: 라우터가 앨범(채팅, 보낸 사람, `media_group_id`) 사진을 모아 두고, `Timing::album_wait`(1초) 동안 다음 사진이 없으면 한 입력으로 넘긴다. 게이트웨이 루프는 폴링과 함께 다음 마감을 기다린다(폴링은 취소해도 넘기지 않은 업데이트가 다시 온다). 같은 채팅의 다른 메시지는 모아 둔 앨범을 먼저 넘긴다(순서 유지). 그보다 늦은 사진은 전처럼 따로 입력이 되고, 그룹은 받아들인 앨범 기억으로 받는다.
- 개인 정보 모드: 실제 텔레그램 없이는 확인할 수 없어 결정과 확인 방법을 문서에 적었다(Bot API 문서의 목록에 멘션 글과 캡션 없는 앨범 사진이 없다. 그룹에서 쓰려면 `/setprivacy`로 끄거나 관리자로).
- `@사용자이름` 알림: 그룹(음수 chat id) 답에서 단어 시작의 `@` + 영문자 뒤에 U+2060을 넣는다. 메일 주소와 개인 채팅은 그대로. 넣은 글자로 길이가 넘으면 다시 나눈다.
- 전달된 메시지와 승인 질문: `Channels::queue`(답 확인 없이 대기열로)를 더해 전달된 메시지는 답이 되지 않고 턴 뒤에 돈다. 그룹에서는 질문 대기만으로 전달된 글을 받지 않는다.
- 테스트: `telegram/bot.rs`의 명령 읽기, `slash::is_command`, `platform.rs`의 멘션 끊기, `tests/telegram_gateway.rs`(개인 채팅의 `/tmp is full`, 두 응답으로 나뉜 앨범이 한 입력, 질문 대기 중 전달된 `n`이 거절이 아니고 턴 뒤 입력, 그룹 답의 멘션). 각 수정을 되돌리면 해당 테스트가 실패하는 것을 확인했다.
- 남은 위험: 실제 텔레그램으로는 돌려 보지 않았다. 앨범 대기 1초만큼 앨범 입력이 늦게 시작한다. U+2060은 복사할 때 따라간다.

### 릴리스와 설치 (로드맵 11단계)
- 새 코드: `.github/workflows/release.yml`, 저장소 루트의 `install.sh`, `src/update/`(`version.rs` semver, `fetch.rs` 받기, `install.rs` 확인과 교체). 공유 파일은 연결만: `lib.rs`, `cli.rs`(`update` 하위 명령, 도움말), `slash.rs`(`/update`), `main.rs`, `self_command::STATE_CHANGING`, doctor `--online`. 문서는 `docs/install.md`.
- 결정: Linux aarch64 musl 교차 빌드는 `cargo-zigbuild`(cross 대신). Docker가 필요 없고 x86_64와 aarch64를 같은 러너에서 같은 방법으로 빌드하며, 같은 도구로 이 서버에서 macOS 대상 `cargo check`(ring의 C 코드를 zig가 컴파일)를 돌려 macOS 빌드 오류를 미리 찾았다. CI에서는 venv에 `cargo-zigbuild`와 `ziglang`을 pip 해시로 고정해 설치한다. macOS 두 대상은 macOS 러너(Apple silicon)에서 그대로 `cargo build`.
- 결정: 출처 증명은 `actions/attest`(v4부터 `attest-build-provenance`가 감싸는 본체)로 압축과 `SHA256SUMS`에. publish일 때만(시험 실행은 증명을 남기지 않는다). 권한은 기본 없음, job마다 필요한 것만(`contents: write`는 release job, `id-token`/`attestations`는 attest job). 액션은 모두 커밋 SHA 고정, 릴리스 빌드는 캐시 없이.
- 결정: 시험 실행. `workflow_dispatch`(`publish` 끔)는 워크플로가 기본 브랜치에 있어야 쓸 수 있어, `release.yml`을 바꾸는 PR에서도 `pull_request` 트리거로 빌드와 `SHA256SUMS`까지 돈다. `publish`를 켠 수동 실행은 `v*` 태그 위에서만.
- 결정: 최신 확인은 GitHub API 대신 `releases/latest`의 리다이렉트(`Location`의 `/tag/<태그>`)를 읽는다. 요청 한도(비인증 시간당 60회)와 JSON 해석이 없고, 릴리스가 없으면 `/releases`로 가는 것을 이 저장소에서 `curl`로 확인했다. 설치 스크립트는 `latest/download/SHA256SUMS`를 받아 파일 이름에서 버전을 읽는다(압축 이름에 버전이 있다).
- 결정: 압축 풀기는 시스템 `tar`(macOS와 Linux 모두 있음)로 비공개 임시 폴더에 멤버 하나만. gzip/tar 크레이트(새 의존성 둘)를 들이지 않았다. 해시는 이미 있는 `ring`.
- 결정: `update`는 `--check`까지 `STATE_CHANGING`에 넣었다(`find`가 뒤 낱말을 보지 않는다). 모델이 확인만 하려 해도 묻는다.

Landlock, `PR_SET_DUMPABLE`은 이미 `cfg(target_os = "linux")`로 갈려 있었다(macOS에서 `sandbox=auto`는 경고, `require`는 거절). CI에 macOS `cargo check --all-targets`(경고는 오류) job, `install.sh`에 shellcheck job을 더했다.

- 새 모듈 `src/slack/`(`mod.rs` 게이트웨이, `config.rs`, `api.rs` Web API, `socket.rs` Socket Mode, `bot.rs` 라우터, `format.rs` mrkdwn, `platform.rs`). 공유 파일은 연결만: `lib.rs`, `main.rs`, `cli.rs`(`gateway slack`/`slack`), `config_file.rs`(키 다섯), `tools/mod.rs`(`SECRET_ENV_VARS`에 두 토큰), `secrets.rs`(`xapp-`), `session.rs`(`SLACK`), `search/`(출처 `slack`), `update/install.rs`(돌고 있는 게이트웨이 안내), `doctor/`. `Platform` 트레이트와 채널 엔진은 바꾸지 않았다(디스코드·텔레그램 동작과 테스트 그대로)
- 결정: 의존성 추가 없음. Socket Mode의 WebSocket은 디스코드 게이트웨이가 이미 쓰는 `tokio-tungstenite`(rustls, webpki roots)로 연다
- 결정: 서식은 평문 대신 Markdown -> mrkdwn 변환. 슬랙은 기본이 mrkdwn이라 평문으로 보내도 `*`, `_`, `~`, 백틱이 서식으로 읽히고 `<`, `>`, `&`는 어차피 이스케이프해야 한다. 굵게/기울임/취소선/링크/제목/목록/인용/코드를 바꾸고 나머지는 이스케이프한다. 짝 없는 표시는 그대로, `__x__`는 바꾸지 않는다. `markdown_text` 인자(슬랙이 Markdown을 직접 해석)는 이스케이프와 멘션 규칙이 문서에 없어 쓰지 않았다. 이스케이프로 모든 `<...>` 멘션이 막히고 `link_names`를 보내지 않아 평문 `@here`도 알림이 아니다
- 결정: 대화 단위는 DM 채널 하나, 채널은 스레드 하나(`<채널>:<thread_ts>`). 채널은 멘션이나 봇의 스레드(이 프로세스가 멘션받은 스레드, 또는 세션 색인에 있는 스레드)일 때만, 그리고 승인 질문이 기다리는 스레드. 중복은 `event_id`와 (채널, `ts`) 두 가지로(같은 멘션이 `message`와 `app_mention`으로 온다)
- 결정: 봉투는 처리 전에 즉시 ack(슬랙 재전송을 줄임). `chat.postMessage`는 중복 방지 키가 없어 연결 실패와 429만 다시 보낸다. 토큰은 Bearer 헤더(민감 표시)로만, 파일은 `files.slack.com` 정확히 일치 + https + 기본 포트에만 토큰을 보내고 리다이렉트는 손으로 같은 규칙 확인 뒤 따른다(reqwest 자동 리다이렉트 끔). 원격 파일은 받지 않는다
- 결정: 타이핑 표시 없음(봇용 API가 없다). 장소 이름은 `chat`(`this chat: ...`)
- 스펙에서 바꾼 것: scope는 실제로 쓰는 것만 문서화했다(`app_mentions:read`, `chat:write`, `im:history`, `files:read`, 선택 `channels:history`/`groups:history`). 스펙 예시의 `im:read`, `users:read`는 쓰는 API가 없어 넣지 않았다. 더한 것: 선택 이벤트 `message.channels`/`message.groups`로 스레드 답글을 멘션 없이, manifest 예시, App Home Messages Tab 안내, 세션 검색/사용량 출처 `slack`
- 스펙에서 미룬 것: setup 마법사의 슬랙 질문, 슬래시 명령과 버튼(스펙대로 범위 밖), 여러 연결로 끊김 없는 교체
- 테스트: 단위(`slack/config.rs` 설정과 토큰 모양·바꿔 넣기·비노출·루프백 주소, `api.rs` 루프백 가짜로 헤더의 토큰과 경로, 토큰 지운 오류, fatal 판별, 429 Retry-After와 끊긴 post 재전송 없음, 파일 호스트 규칙과 같은 호스트 리다이렉트/다른 호스트 거절과 크기 상한, `socket.rs` WebSocket 주소 규칙, `bot.rs` 멘션 지우기와 기억 상한, `format.rs` 이스케이프/인라인/짝 없는 표시/블록/들어온 표기, `platform.rs` 대화 키와 파일 고르기와 질문), `cli.rs`, `secrets.rs`, `search`, `doctor`(오프라인 검사와 `--online` `auth.test`). 통합 `tests/slack_gateway.rs` 9개(가짜 Web API + 가짜 Socket Mode 서버)
- 남은 위험: 실제 슬랙에는 연결해 보지 않았다(가짜 서버만). mrkdwn 변환이 실제 슬랙 화면에서 어떻게 보이는지(중첩, 한글 옆 `_기울임_`)는 확인하지 못했다. ack한 뒤 처리 전에 죽으면 그 이벤트는 다시 오지 않는다. `disconnect` 뒤 새 연결을 여는 짧은 사이에 온 이벤트는 슬랙이 다른 연결로 보내거나 재전송에 맡긴다
