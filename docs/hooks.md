# 훅

훅은 사용자가 정한 명령을 세션의 정해진 시점에 실행하는 기능입니다. 파일을 고친 뒤 포매터를 돌리거나, 특정 명령을 막거나, 턴이 끝나면 알림을 보내거나, 세션을 시작할 때 맥락을 더할 수 있습니다. 훅은 도구 호출이나 입력을 막을 수 있고 모델에게 안내를 더할 수 있지만, 도구의 입력을 바꾸지는 못하고 승인 질문과 명령 정책을 건너뛰게 하지도 못합니다.

훅은 api 백엔드의 대화(터미널, `-p`), 게이트웨이, 대시보드 대화, 예약 작업, 웹훅, `junees mcp serve`, `task`에서 돕니다. claude-code 백엔드는 Claude Code가 도구를 직접 실행하므로 Junees의 훅을 쓰지 않습니다.

## 설정

훅은 `[[hooks]]` 표 하나에 하나씩 적습니다. 세 곳에서 읽습니다.

- `$JUNEES_HOME/config.toml`: 평평한 설정들 뒤에 `[[hooks]]` 표를 둡니다. `junees setup`이 설정 파일을 다시 써도 훅 표는 그대로 남습니다.
- `$JUNEES_HOME/hooks.toml`: 훅 표만 둔 파일입니다. 설정 파일의 훅 다음에 읽습니다.
- 프로젝트의 `.junees/hooks.toml`: 프로젝트 지침 파일을 읽는 범위의 맨 위 폴더(저장소의 맨 위, 저장소가 아니면 HOME 또는 작업 폴더 자신)에 둔 파일입니다. 남이 쓴 파일일 수 있으므로 승인한 뒤에만 실행합니다([보안](#보안)).

```toml
[[hooks]]
event = "pre_tool"          # pre_tool | post_tool | turn_end | session_start | user_prompt
match = "bash|write_file"   # 도구 이름 정규식 (pre_tool, post_tool만). 없으면 모든 도구
command = ["/home/you/.junees/hooks/check.sh"]   # 프로그램과 인자 배열. 셸 문자열은 받지 않음
timeout = "10s"             # 기본 10s, 최대 60s (ms, s, m 단위)
on_error = "allow"          # allow | block (pre_tool, user_prompt만)
```

- `match`는 도구 이름 전체와 맞춰 봅니다. `bash`는 `bash`에만 맞고 `plugin__x__bash_helper`에는 맞지 않습니다.
- `command`의 첫 낱말은 절대 경로이거나 PATH에서 찾을 이름(`/`가 없는 낱말)이어야 합니다. 사용자 훅에서 `/`를 담은 상대 경로(`./scripts/check.sh`, `~/...`)는 설정 오류입니다. 사용자 훅은 어느 프로젝트에서나 묻지 않고 도는데, 상대 경로면 그때 연 저장소의 파일이 실행되기 때문입니다. `~`는 풀리지 않으므로 `/home/you/.junees/hooks/...`처럼 적습니다. 사용자 훅 스크립트는 `$JUNEES_HOME/hooks/`에 두기를 권합니다. 모델의 도구가 쓰지 못하는 폴더입니다.
- 프로젝트 훅은 상대 경로를 쓸 수 있고, 세션의 작업 폴더에서 찾습니다. 다만 `/`를 담은 첫 낱말은 프로젝트 폴더(`.junees`가 있는 폴더)나 작업 폴더 안의 파일로 풀려야 합니다. 첫 낱말이 인터프리터이면 경로처럼 보이는 인자(`/`가 있고 공백이 없는 낱말, `--opt=` 뒤의 값)도 마찬가지입니다. 링크인 폴더(`tools -> /tmp/jt`), `..`, 절대 경로로 그 밖의 파일을 가리키면 그 훅 파일은 읽을 수 없는 파일로 보고 승인하지도 실행하지도 않습니다. `junees hooks list`, `junees doctor`, 시작할 때의 경고가 어느 줄이 어디로 풀리는지 알려 줍니다. 프로젝트 밖의 프로그램은 PATH의 이름(`/`가 없는 낱말)으로 부릅니다.
- 훅이 실행하는 파일이 세션의 작업 폴더 안(프로젝트 훅이면 프로젝트 폴더 안도)에 있으면, 훅을 읽을 때 그 파일의 SHA-256을 고정합니다([보안](#보안)). 고정하는 파일은 `/`를 담은 `command`의 첫 낱말과, 알려진 인터프리터(`sh`, `bash`, `zsh`, `python3`, `python`, `node`, `ruby`, `perl`)가 실행하는 스크립트입니다([인터프리터의 스크립트](#인터프리터의-스크립트)). 프로젝트 훅이면 이 값이 승인에 들어가므로 스크립트가 바뀌면 다시 묻고, 세션 중에 바뀌면 실행하지 않습니다.
- 사용자 훅(설정 파일과 `hooks.toml`)에 잘못된 값이 있으면(모르는 이벤트, 깨진 정규식, 문자열로 쓴 `command`, 60초를 넘는 `timeout`, 막을 수 없는 이벤트의 `on_error = "block"` 등) Junees가 시작하지 않고 파일과 줄을 알립니다. 정책 훅이 조용히 빠지면 막아야 할 호출이 통과하기 때문입니다.

### 인터프리터의 스크립트

`command`의 첫 낱말이 알려진 인터프리터(파일 이름으로 봅니다. `/usr/bin/python3`도 `python3`이고, 버전이 붙은 `python3.12`, `node22`, `perl5.36`도 같습니다)이면, 옵션 뒤의 첫 인자를 그 인터프리터가 실행하는 스크립트로 보고 첫 낱말처럼 고정합니다. 상대 경로는 작업 폴더에서 찾으므로 `["sh", "check.sh"]`처럼 `/`가 없어도 됩니다.

```toml
command = ["python3", "-u", "scripts/check.py"]   # scripts/check.py를 고정
command = ["bash", "-o", "pipefail", "x.sh"]      # x.sh를 고정
command = ["sh", "-c", "./x.sh"]                  # 고정하지 않음 (doctor가 경고)
```

- 코드나 모듈을 주는 옵션(`sh -c`, `python3 -c`/`-m`, `node -e`/`-p`/`-r`/`--require`/`--import`, `ruby -e`/`-r`/`-C`, `perl -e`/`-E`/`-M`/`-m`/`-x`)이 먼저 오면 고정할 파일이 없습니다. `-ec`처럼 묶어 쓴 옵션도 같습니다.
- 값을 받는 옵션(`bash -o pipefail`, `python3 -W ignore`, `ruby -I lib`)은 그 값을 건너뜁니다. 그 밖의 `-`로 시작하는 낱말은 값이 없는 옵션으로 보고, `--` 뒤의 낱말은 언제나 파일입니다. Junees가 모르는 옵션이 값을 따로 받으면 그 값을 파일로 보아 고정하려 하고, 없는 파일이라 훅이 돌지 않습니다. 그럴 때는 `--opt=value`처럼 붙여 씁니다.
- 스크립트가 작업 폴더 안에 없으면(아직 없는 파일 포함) 고정할 수 없으므로 훅이 돌지 않습니다. 모델이 세션 중에 그 파일을 만들어 넣는 것을 막기 위해서입니다.
- 옵션 해석은 추측이라서, Junees가 모르는 옵션이 값을 받으면 다른 파일을 스크립트로 잘못 고를 수 있습니다(`node --title ./a.js ./b.js`는 `b.js`를 실행합니다). 그래서 인터프리터에 넘긴 나머지 인자 가운데 작업 폴더(프로젝트 훅이면 프로젝트 폴더도) 안의 있는 파일을 가리키는 것도 모두 고정합니다. `--opt=./x`와 `-I./x`처럼 붙여 쓴 값도 봅니다. 이 파일들은 실행 직전에 해시만 확인하고 사본으로 바꾸지는 않습니다. 사본으로 실행하는 것은 스크립트로 읽은 자리 하나입니다.
- 그래서 세션 중에 바뀌는 파일(모델이 고칠 소스 파일 등)을 인터프리터 훅의 인자로 넘기면, 그 파일이 바뀐 뒤로 훅이 돌지 않습니다(`pre_tool`, `user_prompt`는 막음). 고친 파일은 인자 대신 표준 입력의 `tool.input`에서 읽습니다.
- 폴더 인자는 고정하지 않습니다. `ruby -I lib`처럼 폴더를 넘기는 것은 흔하고, 폴더 전체를 해시할 수 없기 때문입니다.
- 스크립트가 다시 부르는 파일(`import`, `source`, `require`)은 고정하지 않습니다([보안](#보안)).

## 이벤트

| 이벤트 | 언제 | 막을 수 있나 |
|---|---|---|
| `session_start` | 새 대화의 첫 입력 전(`/new` 뒤 포함). 이어 가는 세션(`-c`, `--resume`)에서는 돌지 않습니다 | 아니요 |
| `user_prompt` | 사람의 입력이 모델에게 가기 전 | 예 |
| `pre_tool` | 도구 호출 전, 승인 질문 전 | 예 |
| `post_tool` | 도구 호출 뒤(막히거나 거절된 호출 포함) | 아니요 |
| `turn_end` | 턴이 끝난 뒤(답, 오류, 취소 모두) | 아니요 |

서브에이전트(`delegate`)의 도구 호출에도 위임한 세션의 `pre_tool`, `post_tool` 훅이 돕니다. `user_prompt` 훅에 막힌 입력에는 `turn_end` 훅이 돌지 않습니다.

### 도구 호출 하나의 순서

1. 사용자 훅과 프로젝트 훅의 `pre_tool`(설정 순서대로). 하나가 막으면 2~4는 없고 5로 갑니다.
2. 승인 질문과 정책(명령 정책, 파일 도구의 경로 검사, 무인 실행의 거절).
3. 플러그인의 `pre_tool` 훅([플러그인](plugins.md)).
4. 도구 실행.
5. `post_tool` 훅(막히거나 거절된 호출에도 돎).

`delegate`와 `draft` 호출에는 1, 4, 5만 있습니다. 승인 질문과 플러그인 훅은 이 둘에 돌지 않습니다(서브에이전트가 부르는 도구는 각자 이 순서를 다시 거칩니다).

## 실행 계약

### 입력

표준 입력으로 JSON 객체 하나를 받습니다.

```json
{
  "event": "pre_tool",
  "session_id": "20261117-101500-ab12",
  "cwd": "/home/me/project",
  "tool": {"name": "bash", "input": {"command": "cargo test"}},
  "result": {"is_error": false, "text": "..."},
  "prompt": "..."
}
```

- `session_id`: 세션 기록의 id. 기록하지 않는 세션이면 `null`입니다.
- `tool`: `pre_tool`, `post_tool`에만 있습니다.
- `result`: `post_tool`에서는 도구 결과, `turn_end`에서는 모델의 답(오류면 오류 글, 취소면 `cancelled`)입니다. `text`는 앞 16KB(문자 경계에서 자름)입니다.
- `prompt`: `user_prompt`에만 있습니다.
- 모든 문자열에서 알려진 비밀 값(설정과 환경의 키, 토큰)을 가린 뒤 넘깁니다. 가린 뒤에 자르므로 잘린 키 조각이 남지 않습니다.

### 환경과 작업 폴더

- 작업 폴더는 세션의 작업 폴더입니다.
- 환경 변수는 bash 도구와 같은 규칙으로 지웁니다: 비밀 변수 목록(`ANTHROPIC_API_KEY` 등), Claude Code 로그인 변수, `JUNEES_HIDDEN_ENV`, 그리고 이름에 `KEY`, `TOKEN`, `SECRET`, `PASSWORD`가 든 `JUNEES_*` 변수. 더하는 변수는 `JUNEES_HOOK_EVENT`(이벤트 이름), `JUNEES_SESSION_ID`(세션 id, 없으면 지움), `JUNEES_HOOK_FILE`(아래) 셋입니다.
- 고정한 파일이 있는 훅은 원래 파일이 아니라 확인한 바이트의 사본을 실행합니다([보안](#보안)). 사본은 `$JUNEES_HOME/hook-copies/<임의 이름>/` 아래에 원래 파일 이름 그대로 있고, 실행이 끝나면 지웁니다. 그래서 스크립트의 `$0`(파이썬의 `__file__`, 노드의 `__dirname`)은 사본을 가리킵니다. 대신 `JUNEES_HOOK_FILE`에 원래 경로(인터프리터의 스크립트, 없으면 프로그램)가 있으니, 자기 위치를 기준으로 다른 파일을 찾는 스크립트는 이 변수를 씁니다. 사본을 실행하지 않는 훅에서는 이 변수를 지우므로, 셸에서는 `"${JUNEES_HOOK_FILE:-$0}"`처럼 쓰면 어느 쪽이든 원래 경로가 됩니다.

```sh
here=$(dirname "${JUNEES_HOOK_FILE:-$0}")
. "$here/lib.sh"
```

- 파이썬은 스크립트 폴더를 `sys.path`에 넣으므로 사본에서는 옆 모듈을 `import`하지 못합니다. `sys.path.insert(0, os.path.dirname(os.environ.get("JUNEES_HOOK_FILE", __file__)))`처럼 넣습니다. 노드의 상대 `require`도 같습니다. 이렇게 불러 온 파일은 고정되지 않습니다.
- 사본은 원래 파일에 실행 권한(`x`)이 있을 때만 실행할 수 있게 만듭니다. 원래 파일을 실행할 수 없으면 사본도 전처럼 실패합니다.
- 훅은 자기 세션(setsid)에서 돌아 Junees의 터미널을 열 수 없습니다. bash 도구의 샌드박스(Landlock, [실행 격리](safety.md#실행-격리-landlock))가 켜져 있으면 훅에도 같은 규칙을 씁니다. 샌드박스가 실행을 거절하면 훅이 실패한 것으로 봅니다.
- 시간이 넘으면 훅의 프로세스 그룹을 통째로 끝냅니다. 턴이 취소되면 도는 `pre_tool`, `post_tool`, `session_start`, `user_prompt` 훅도 끝냅니다.

### 결과

| 결과 | 뜻 |
|---|---|
| 종료 코드 0 | 계속합니다. 표준 출력(앞 16KB)이 `{"message": "..."}`이면 그 글(최대 4000자)을 모델에게 Junees의 안내로 더합니다 |
| 종료 코드 2 (`pre_tool`, `user_prompt`) | 막습니다. 표준 오류의 앞 2KB가 막은 이유입니다 |
| 그 밖의 코드, 신호, 시간 초과, 시작 실패 | `on_error`를 따릅니다. `allow`(기본)이면 경고 한 줄을 남기고 계속하고, `block`이면 막습니다 |
| 고정한 파일이 바뀜, 없음, 링크, 너무 큼 | 실행하지 않습니다. `pre_tool`, `user_prompt`에서는 `on_error`와 상관없이 막고, 다른 이벤트에서는 경고합니다 |

- `pre_tool` 훅이 막으면 그 호출은 실행되지 않고, 승인 질문도 나오지 않습니다. 모델은 `not run: the pre_tool hook \`<명령>\` blocked this: <이유>` 오류 결과를 받습니다.
- `pre_tool` 훅이 통과시켜도 승인 질문과 명령 정책은 그대로 적용됩니다. 훅은 입력을 바꾸지 못합니다. 바꿀 수 있다면 승인 화면에서 본 것과 실제 실행이 달라지기 때문입니다.
- `user_prompt` 훅이 막으면 입력이 모델에게 가지 않고, 터미널에는 `the message was not sent: ...` 오류가 나옵니다. 세션 기록에는 막았다는 안내 줄만 남고 입력은 남지 않습니다.
- 종료 코드 2는 `post_tool`, `turn_end`, `session_start`에서는 막지 않고 실패로 봅니다(경고).
- 같은 이벤트의 훅은 설정 순서(설정 파일, `hooks.toml`, 프로젝트 파일)대로 하나씩 돌고, 하나가 막으면 뒤의 훅은 돌지 않습니다. `post_tool`, `turn_end`는 끝날 때까지 기다리지만 실패해도 턴을 멈추지 않습니다.

### 세션 기록과 모델이 보는 것

훅이 돌 때마다 세션 기록에 Junees의 안내 줄(`notes` 항목, 모델에게는 `<junees_notice>` 블록)이 한 줄 남습니다. 세션 기록 형식은 9 그대로입니다.

```
[훅] pre_tool `./scripts/check.sh`: 막음 (0.05초)
[훅 post_tool `cargo fmt`] formatted 2 files
```

- 결과는 `통과`, `막음`, `실패`, `시간 초과(N초)`이고, `on_error = "block"`으로 막았으면 `실패 시 막는 설정이라 막음`이 붙습니다.
- 고정한 파일이 바뀌어 실행하지 않았으면 `실패, 훅이 부르는 파일이 바뀌어 실행하지 않았습니다`, 훅을 읽을 때 고정하지 못했으면(없음, 링크, 너무 큼) `실패, 훅이 부르는 파일을 고정하지 못해 실행하지 않았습니다`입니다. 그래서 막았으면 `확인하지 못한 파일이라 막음`이 붙습니다.
- `message`는 두 번째 줄처럼 따로 남습니다. 제어 문자와 방향 바꾸기 문자는 이스케이프하고, 알려진 비밀 값은 가리고, `<junees_notice>` 태그는 깨뜨려서(#117/#125 규칙) 훅 출력이 Junees의 안내 블록을 열거나 닫지 못하게 합니다.
- 도구 훅의 줄은 그 도구 라운드의 결과 뒤에, `session_start`와 `user_prompt` 훅의 줄은 입력 앞에, `turn_end` 훅의 줄은 턴이 끝난 뒤(다음 입력과 같은 메시지)에 들어갑니다.
- 터미널과 게이트웨이는 같은 줄을 진행 표시로 보여 줍니다. 대시보드 대화에는 `hook` 이벤트를 보냅니다.

```json
{"type": "hook", "event": "pre_tool", "command": "./scripts/check.sh", "origin": "user",
 "result": "blocked", "took_ms": 52, "reason": "rm is not allowed here"}
```

`result`는 `passed`, `blocked`, `timed_out`, `failed`이고, `message`(통과하며 남긴 글), `reason`(막은 이유), `error`(실패 이유), `blocked: true`(실패로 막음)는 있을 때만 붙습니다. `origin`은 `user` 또는 `project`입니다.

## 예제

### 파일을 고친 뒤 포매터 돌리기

```toml
[[hooks]]
event = "post_tool"
match = "write_file|edit_file"
command = ["/home/you/.junees/hooks/fmt-hook.sh"]
timeout = "30s"
```

```sh
#!/bin/sh
# ~/.junees/hooks/fmt-hook.sh: 고친 파일이 .rs이면 rustfmt를 돌리고 모델에게 알린다.
path=$(jq -r '.tool.input.path // empty')
case "$path" in
  *.rs) rustfmt --edition 2024 "$path" && echo '{"message": "rustfmt로 정리했습니다. 다시 읽고 이어 가세요."}' ;;
esac
```

### 명령 막기

```toml
[[hooks]]
event = "pre_tool"
match = "bash"
command = ["/home/you/.junees/hooks/no-force-push.sh"]
on_error = "block"   # 훅이 실패해도 막는다
```

```sh
#!/bin/sh
# ~/.junees/hooks/no-force-push.sh: force push를 막는다.
if jq -r '.tool.input.command' | grep -Eq 'git push.*(--force|-f)'; then
  echo "force push는 사람이 직접 합니다" >&2
  exit 2
fi
```

### 턴이 끝나면 알림 보내기

```toml
[[hooks]]
event = "turn_end"
command = ["notify-send", "Junees", "턴이 끝났습니다"]
```

## 명령

- `junees hooks` 또는 `junees hooks list`: 이 폴더의 세션이 읽는 사용자 훅과 프로젝트 훅, 프로젝트 파일의 승인 상태를 보여 줍니다.
- `junees hooks trust`: 이 폴더의 프로젝트 훅 파일을 지금 내용 그대로 승인하고, 승인한 내용을 보여 줍니다.
- `junees hooks untrust`: 그 파일의 승인을 거둡니다.
- `junees hooks test <event> [--tool <name>]`: 그 이벤트의 훅(사용자 훅과 승인된 프로젝트 훅)을 예시 입력(`session_id`는 `hooks-test`, 도구 입력은 `{}`, 결과와 프롬프트는 `test`)으로 한 번 돌리고 결과를 보여 줍니다.
- `junees doctor`: 훅마다 프로그램이 있는지, 프로젝트 파일이 읽히는지와 승인 상태를 점검합니다. 사용자 훅이 깨져 있으면 실패로 표시합니다. 고정할 수 없는 저장소 파일을 간접으로 실행하는 훅에는 경고를 냅니다: 빌드 도구(`make`, `npm`, `npx`, `yarn`, `pnpm`, `fmt`가 아닌 `cargo` 하위 명령. `cargo fmt`는 rustfmt만 부르므로 경고하지 않습니다), 코드나 모듈을 받은 인터프리터(`sh -c`, `python3 -m`, `node -r`/`--require` 등. 그 코드가 작업 폴더의 파일을 부르면 그 파일은 고정되지 않는다는 뜻입니다), Junees가 모르는 인터프리터(`dash`, `ksh`, `deno`, `bun`, `php` 등, 버전이 붙은 이름 포함), 다른 명령을 감싸 실행하는 명령(`env`, `timeout`, `nice`, `nohup`, `xargs`, `exec`, `sudo`, `time`. 감싼 명령은 고정하지 않습니다), 상대 경로의 스크립트를 인터프리터로 실행하는 사용자 훅(그때 연 프로젝트의 파일이 실행됨).

## 훅이 실행되지 않을 때

먼저 아래 두 명령으로 확인하세요. 일반 세션은 문제가 난 세션과 같은 작업 폴더에서 점검하세요. 웹훅의 프로젝트 훅 설정과 승인 상태는 임시 worktree가 아니라 웹훅 경로에 등록한 원래 폴더에서 확인하세요([보안](#보안)). 두 명령 모두 훅을 실행하거나 승인 기록을 바꾸지 않습니다. 출력만으로는 실제 실행에서 훅이 동작했는지나 그 결과를 알 수 없습니다.

- `junees hooks list`: 현재 폴더의 사용자 훅과 프로젝트 훅을 나열합니다. 프로젝트 훅 파일의 경로와 승인 상태, 각 훅의 이벤트와 명령을 확인할 수 있습니다.
- `junees doctor`: 보고서의 `hooks` 구역에서 설정과 승인 상태, 훅에 적힌 프로그램을 찾을 수 있는지 확인하세요. 프로그램을 찾았다는 결과는 훅이 실제로 실행됐다는 뜻이 아닙니다.

프로젝트 훅 설정이 유효해도, `not trusted`만으로는 승인 이력이 없는지 이전 승인과 달라졌는지 구분할 수 없습니다. 시작할 때 나온 경고나 오류를 함께 확인하세요.

### 시작할 때 승인 여부를 묻거나 실행을 중단하는 경우

아래 규칙은 Junees 훅을 사용하는 `api` 백엔드에 적용됩니다. `claude-code` 백엔드는 Junees 훅을 사용하지 않습니다. 유효한 프로젝트 훅에 최초 승인이나 재승인이 필요하면, 상태 폴더가 있고 표준 입력과 표준 오류가 모두 터미널인 대화 모드에서만 파일을 보여 주고 승인 여부를 묻습니다. `-p`, 게이트웨이, 대시보드 대화, 예약 작업, 웹훅, `task`에서는 묻지 않습니다.

- **승인 이력이 없는 유효한 설정.** 터미널 대화에서 거절하거나 승인 없이 입력을 끝내거나 승인 저장에 실패하면, 경고를 남기고 프로젝트 훅만 빼고 시작합니다. 무인 실행에서도 질문 없이 경고를 남기고 프로젝트 훅만 빼고 시작합니다.
- **유효한 설정이 기존 승인과 달라진 경우.** 훅 설정이나 승인 때 확인한 스크립트가 바뀌면 재승인이 저장되어야 시작합니다. 터미널 대화에서 거절하거나 승인 없이 입력을 끝내거나 저장에 실패하면 시작하지 않습니다. 무인 실행은 질문 없이 오류로 중단합니다. 이전에 승인한 내용과 현재 설정 및 스크립트의 차이를 직접 확인하고, 변경을 받아들일 때만 재승인하세요. 무인 실행에 다시 적용하려면 사람이 프로젝트에서 `junees hooks trust`로 재승인을 저장한 뒤 실행을 다시 시작하세요.
- **이전에 승인한 프로젝트 훅 설정을 검증할 수 없는 경우.** 승인 기록을 정상적으로 읽었더라도, 프로젝트 훅 설정 파일이 없거나 읽기·파싱에 실패하면 시작을 중단합니다. 승인에 포함할 파일의 경로를 확인하거나 해시를 계산할 수 없을 때도 마찬가지입니다. 터미널에서도 재승인 질문을 띄우기 전에 오류가 나므로, 먼저 오류에 표시된 설정이나 파일을 확인하고 고치세요. 승인 이력이 없는 프로젝트에서 잘못된 설정을 발견하면 경고를 남기고 그 프로젝트 훅은 실행하지 않습니다.
- **승인 기록 자체를 읽거나 해석할 수 없는 경우.** `trusted-hooks` 파일이 없는 경우와, 파일을 읽을 수 없거나 형식이 잘못된 경우는 다릅니다. 읽기·형식 오류는 미승인으로 처리하지 않습니다. 훅을 로드하는 세션과 `hooks list`가 오류로 중단되고, `doctor`는 `hooks` 구역의 `trusted-hooks` 항목을 `FAIL`로 표시한 뒤 프로젝트 훅 점검을 중단합니다. `hooks trust`와 `hooks untrust`도 이 기록을 읽어야 하므로, 먼저 오류가 가리키는 기록의 경로와 원인을 확인하세요.

프로젝트 훅을 더 이상 사용하지 않기로 결정했다면, 승인 기록이 정상일 때 `junees hooks untrust`로 해당 프로젝트의 승인을 명시적으로 철회할 수 있습니다. 훅을 계속 사용해야 한다면 철회하지 말고 설정 오류나 승인 불일치의 원인을 확인하세요.

### `hooks test`를 쓰기 전에

**`junees hooks test <event>`는 읽기 전용 점검이 아닙니다.** 먼저 훅 설정과 승인 상태를 확인하며, 승인 여부를 묻지 않습니다. 기존 승인과 불일치하거나, 이전에 승인한 프로젝트 훅 설정을 검증할 수 없거나, 승인 기록에 읽기·형식 오류가 있으면 사용자 훅도 실행하기 전에 오류로 끝납니다. 승인 이력이 없는 프로젝트 훅은 경고를 남기고 제외합니다.

설정 오류가 있거나 샌드박스가 적용되는지 확인하지 못했다면 `hooks test`를 실행하지 마세요. 실행 전에 어떤 훅이 실행되는지, 어떤 부작용이 생길 수 있는지 확인하세요.

훅을 정상적으로 불러오면 지정한 이벤트에 맞는 사용자 훅과 승인된 프로젝트 훅을 예시 입력으로 실제 실행합니다. 도구 이벤트에서는 예시 입력의 도구 이름이 훅의 `match` 조건에도 맞아야 합니다. 조건에 맞는 훅이 없으면 아무 훅도 실행하지 않으며, 차단이 발생하면 뒤의 훅은 실행하지 않습니다. 원인을 확인하는 첫 단계에서는 `hooks list`와 `doctor`를 사용하세요.

## 보안

- 사용자 훅(`$JUNEES_HOME`)은 사용자가 쓴 것이므로 묻지 않고 실행합니다. 모델의 도구는 `$JUNEES_HOME/hooks.toml`과 승인 기록 `$JUNEES_HOME/trusted-hooks`를 읽지도 쓰지도 못합니다. 파일 도구, 명령 정책, bash 샌드박스(작업 폴더가 상태 폴더를 품을 때도) 모두에서 설정 파일과 같은 보호를 받습니다([명령 정책](safety.md#명령-정책)). `$JUNEES_HOME/hooks/` 폴더는 모델이 읽을 수만 있습니다. 쓸 수 있다면 모델이 묻지 않고 실행될 명령을 심거나 프로젝트 훅을 스스로 승인할 수 있기 때문입니다.
- 프로젝트 훅(`.junees/hooks.toml`)은 저장소에 들어 있는 남의 코드이므로 사람이 승인해야 실행합니다. 승인은 파일 경로와 내용의 SHA-256으로 기록하므로(`$JUNEES_HOME/trusted-hooks`, 0600) 한 글자라도 바뀌면 다시 묻습니다. 링크인 파일, 일반 파일이 아닌 것, 256KB가 넘는 파일은 읽지 않습니다.
- 승인 기록 파일이 없으면 처음 실행한 것으로 처리합니다. 파일이 있지만 읽을 수 없거나 내용이 잘못됐으면 경로와 원인을 표시하고, 세션을 시작하거나 `hooks list`, `trust`, `untrust`를 계속하지 않습니다. `trusted-hooks`의 읽기와 저장 한도는 모두 256 KiB입니다. 기록을 추가하면 이 한도를 넘는 경우 기존 기록은 그대로 남습니다.
- `hooks trust`, `hooks untrust`, 대화에서의 재승인은 같은 잠금을 잡고 최신 기록을 읽어 해당 항목만 바꾼 뒤 파일을 한 번에 교체합니다. 프로젝트 훅 검증과 승인 질문은 잠금 밖에서 합니다. 기록 파일은 교체되므로 잠금은 교체하지 않는 별도 파일 `$JUNEES_HOME/trusted-hooks.lock`(0600)에 둡니다. 이 파일도 승인 기록과 같은 도구 보호를 받으며, 실행 중에는 지우지 마세요. 다른 Junees가 잠금을 계속 잡고 있으면 현재 기록을 바꾸지 않고 다시 시도하라는 오류를 냅니다.
- 승인 기록이 남아 있는 프로젝트 훅 설정이 없어졌거나, 읽기·파싱·경로 또는 해시 검증에 실패하면 원인을 표시하고 실행을 시작하지 않습니다. 설정과 입력을 고치거나, 훅을 빼기로 했다면 `junees hooks untrust`로 기존 승인을 명시적으로 지우세요. 승인 이력이 없는 잘못된 설정은 경고만 내고 그 프로젝트 훅을 실행하지 않습니다.
- 터미널 대화(표준 입력과 표준 오류가 모두 터미널)는 시작할 때 파일 내용 전체를 보여 주고 실행할지 묻습니다. 처음 보는 설정은 거절하면 훅만 빼고 시작합니다. 승인 기록과 현재 내용이 다르면 재승인이 저장되어야 시작합니다. 거절하거나 저장에 실패하면 실행을 시작하지 않습니다.
- 물을 사람이 없는 실행(`-p`, 게이트웨이, 대시보드 대화, 예약 작업, 웹훅, `junees mcp serve`, `task`)은 승인 이력이 없는 프로젝트 훅을 실행하지 않고 경고만 냅니다. 기존 승인과 현재 내용이 다르면 `junees hooks trust`로 재승인하거나 `junees hooks untrust`로 기존 승인을 철회하기 전까지 실행을 시작하지 않습니다. 웹훅 실행은 지침 파일처럼 경로 폴더의 프로젝트 파일을 봅니다.
- 모델이 bash로 `junees hooks trust`/`untrust`를 실행하려 하면 Junees 자신의 상태를 바꾸는 명령으로 보고 승인을 묻거나(대화) 막습니다(무인 실행).
- 훅 명령은 bash 도구와 같은 비밀 변수 제거와 샌드박스 아래에서 돕니다. 다만 샌드박스가 꺼져 있으면 훅은 사용자 권한 그대로 돕니다.
- 훅 실행은 명령 정책과 승인 질문을 거치지 않습니다. 그래서 훅이 실행하는 파일이 세션의 작업 폴더 안에 있으면(모델이 `write_file`로 묻지 않고 고칠 수 있는 곳) 훅을 읽을 때 그 파일의 SHA-256을 고정합니다. 프로젝트 훅이면 이 값이 승인 digest에 들어가 스크립트가 바뀌면 다음 세션에서 다시 묻고, 승인 질문에도 고정한 파일이 보입니다. 실행 직전에 다시 계산해 다르면 실행하지 않습니다. 파일이 없거나, 링크이거나, 16MB가 넘으면 고정할 수 없으므로 실행하지 않습니다.
- 고정 실패는 훅이 고장 난 것이 아니라 누군가 파일을 바꿨다는 신호입니다. 그래서 막을 수 있는 이벤트(`pre_tool`, `user_prompt`)에서는 `on_error`와 상관없이 막습니다. 그렇지 않으면 모델이 작업 폴더 안의 정책 훅 스크립트를 고치는 것만으로 그 훅을 빼고 막으려던 호출을 통과시킬 수 있습니다. 다른 이벤트에서는 경고를 남기고 계속합니다. 사용자 훅이 부르는 작업 폴더 밖의 절대 경로와 PATH의 프로그램은 고정하지 않습니다. 프로젝트 훅은 프로젝트 폴더나 작업 폴더 밖으로 풀리는 경로를 아예 받지 않으므로, `/`를 담은 프로젝트 훅의 첫 낱말은 언제나 고정됩니다. 승인한 사람이 본 `./tools/check.sh`가 다른 사용자나 모델이 바꿀 수 있는 `/tmp/jt/check.sh`로 풀려 고정 없이 도는 일을 막기 위해서입니다.
- 일반 인자와 `--옵션=값`, 짧은 옵션에 붙인 값은 같은 기준으로 검사합니다. 프로그램으로 지정한 경로와 스크립트로 판별한 인자 외에는 `./`, `../`, `/`로 시작하는 값을 명시적 경로로 봅니다. `team/default`처럼 이 접두사가 없는 값은 실제로 존재하는 경로를 가리킬 때만 검사합니다. 프로젝트 훅은 검사 대상 경로가 프로젝트나 세션 작업 폴더 밖으로 풀리면 승인할 수 없습니다. 폴더는 범위만 확인하고 그 내용은 고정하지 않습니다.
- 명시적인 입력이 없거나 고정 대상의 해시를 계산하지 못하면 파일과 원인을 표시하고 승인 저장을 거절합니다. 기존 승인 기록은 그대로 둡니다. 훅이 만드는 출력 파일이라도 명시적인 경로 인자로 넘기면 같은 검사를 받으므로, 아직 없는 출력 경로는 승인한 훅 내부에서 정하세요. 고정 목록과 해시가 그대로라면 기존 승인이 유지됩니다. 검증 가능한 상태라도 목록이나 해시가 바뀌면 새 승인이 필요합니다. 실행 직전에도 같은 기준으로 인자 경로를 풀어 승인 당시의 고정 목록과 대조합니다.
- 모델이 고칠 수 있는 파일을 실행하는 훅은 모델에게 정책 밖 실행을 줍니다. 고정은 `command`의 첫 낱말이 가리키는 파일과 알려진 인터프리터의 파일 인자에 적용합니다. 프로그램과 스크립트로 판별한 인자는 사본으로 실행하고, 나머지 파일 인자는 해시만 확인하므로 확인과 사용 사이에 바뀔 수 있습니다. `make`, `npm run`, `cargo build`(Makefile, package.json, build.rs), 인터프리터의 `-c`/`-m`, `env`나 `timeout`으로 감싼 명령, Junees가 모르는 인터프리터, 스크립트가 다시 부르는 다른 파일처럼 저장소 내용을 간접으로 실행하는 훅은 막을 수 없습니다. `junees doctor`가 이런 훅에 경고를 냅니다. 훅 스크립트는 작업 폴더 밖(`$JUNEES_HOME/hooks/`)에 두거나 `command`의 첫 낱말 또는 인터프리터의 스크립트 인자로 직접 부릅니다.
- 고정한 프로그램과 스크립트는 실행 직전에 해시를 확인한 바이트를 `$JUNEES_HOME/hook-copies/`의 새 0700 폴더에 써서 그 사본을 실행합니다. 그 밖의 입력 파일은 해시만 대조하고 사본을 만들지 않습니다. `hook-copies`는 `hooks`처럼 데이터 폴더라서 파일 도구와 명령 정책은 쓰기를 거절하고, bash 샌드박스에서는 읽기 전용입니다. 샌드박스가 꺼져 있으면 같은 사용자 권한으로 도는 프로세스가 사본까지 바꿀 수 있습니다. 사본을 만들지 못하면(디스크가 가득 참, `hook-copies`가 링크 등) 훅을 실행하지 않고 훅 실패로 처리합니다(`on_error`를 따름).
- `sandbox_read`로 읽을 수 있는 폴더를 좁혔다면, 고정한 파일이 있는 훅을 위해 `$JUNEES_HOME/hook-copies`도 넣어야 합니다. 사본을 읽지 못하면 그 훅은 실패합니다.
- 승인 질문은 파일 원문 다음, `[y/N]` 바로 위에 파싱한 결과(훅 N개, 훅마다 이벤트, match, 명령, 고정한 파일)를 보여 줍니다. 긴 파일에서 빈 줄로 훅 하나를 화면 밖에 밀어내도 실제로 돌 것이 보입니다.
- 훅에 넘기는 입력은 알려진 비밀 값을 가리지만, 파일 내용이나 명령 출력에 든 모르는 비밀까지 가리지는 못합니다. 훅이 입력을 밖으로 보낸다면 그 점을 생각하고 씁니다.
